# G3 Data Quality Spike（硬事实字段数据质量分析）

> 工作流 G3 阶段的风险前置验证。**不依赖 API key，用公开网页数据离线分析。**
> 目的：量化「开放时间/闭馆日」这类硬事实字段在公开源里的**覆盖率、一致性、失败模式**，
> 回答「数据到底乱不乱、乱在哪、求解器该怎么建模」。结论已落 ADR-0002。

## 方法

- 数据源：WebSearch 聚合（百度百科 / 杭州本地宝 / Trip.com / 官方公示等多源）。
- 样本：9 个杭州景点，覆盖不同类型（开放式景点 / 博物馆 / 塔 / 湿地 / 演出 / 乐园）。
- 测量项：开放时间是否可解析、闭馆日是否明确、多源是否一致、是否存在季节性/政策变更。
- **本 Spike 未测量 LLM 抽取精度**（需 LLM API + 人工金标准标注），见「局限」。

## 原始数据与失败模式

| 景点 | 开放时间 | 闭馆日 | 暴露的失败模式 |
|---|---|---|---|
| 西湖 | 全年 24h 免费开放，无门禁 | 无 | **无固定开放时间**（开放式景点） |
| 灵隐寺 | 7:30–17:30（17:00 停止入园） | 无 | **政策变更**：2025-12 起免票 + 分时预约（上午/下午场） |
| 浙江省博物馆 | 9:00–17:00（16:30 停止入馆）；暑期延长至 19:30 | **周一闭馆（遇法定节假日顺延）** | 闭馆日**有例外** + 季节性延长 |
| 中国伞博物馆 | 9:00–16:30（16:00 停止入场） | 旧资料周一闭馆 → **2023-07 起改为周二闭馆** | **闭馆日字段过期**（政策调整，最致命） |
| 雷峰塔 | 冬 8:00–17:30 / 夏 8:00–19:00 | 无 | 季节性双套时间 + **多源价格冲突**（40 vs 95 元） |
| 西溪湿地 | 夏令 7:30–18:30 / 冬令 8:00–17:30 | 无 | 双套时间 + 多级时间（停止售票/停止入园/闭园）+ 多源不一致 |
| 宋城 | 10:00–21:00（随最后一场演出顺延 30min） | 无 | **闭园时间动态** + 演出场次多源冲突（14/17/19:00 vs 18:40/20:00） |
| 杭州乐园 | 工作日/周末/节假日三套时间 | **每年 12/1–3/6 整季闭园** | 季节性闭园 + 三套时间 |
| 六和塔 | 7:00–17:30（夏令/冬令略异） | 无 | 门票组合（20 门票 + 10 登塔）+ 多源不一致 |

## 失败模式分类（5 类，按严重度）

1. **🔴 闭馆日时效性**：伞博物馆 2023 从「周一闭馆」改「周二闭馆」——静态数据会把用户排到错误的日子。这是**最低级错误**的直接来源（正是产品要杜绝的）。
2. **🔴 时间语义不统一**：一个景点有「停止售票/停止入园/清场/闭园」多个时间口径，不同源混用。求解器必须锁定**「有效入园截止」**（= 最晚能进并完成游览的时间）。
3. **🟠 季节性/多套时间**：夏令/冬令（雷峰塔、西溪、六和塔）、工作日/周末/节假日（杭州乐园、宋城）、暑期延长（省博物馆）。单一 `open_time`/`close_time` 字段无法表达。
4. **🟠 无固定开放时间**：西湖等开放式景点没有开放时间，需要「全天开放」标记，否则求解器误判。
5. **🟡 政策/预约制变更**：灵隐寺免票+分时预约、杭州打破「周一闭馆」惯例——这类变更不体现在「开放时间」字段，但直接影响行程可行性。

## 核心结论

1. **数据本身比 LLM 抽取更危险**：即使 LLM 100% 抽准，也会抽到「周一闭馆」（过期）或「10:00–21:00」（但实际随演出顺延）。**数据保鲜 + 人工校准 > 抽取精度**。
2. **数据模型要支持「按日期区间的多套时间窗」**，而非单一 open/close（详见 ADR-0002）。
3. **高影响字段应 100% 人工校准**：P1 这 80–120 个景点的「开放时间 + 闭馆日」必须 `data_verified=1` 才进求解器（失败后果严重、样本量小、可承受）。

## 局限

- 未测 LLM 抽取端到端精度（需 LLM API + 金标准）。但上述分析表明**覆盖/一致性/时效**是更前置的瓶颈，应先解决。
- 样本 9/20（目标 20 个）；失败模式已饱和，追加样本主要影响比例而非类别。
