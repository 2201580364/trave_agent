# 假设验证与复盘技能

> 工作流收尾阶段：回答「假设成立吗？失败错在哪一层？」

## 步骤

1. **执行验证**：按假设登记册的验证方式执行，并区分 E1 Spike、E2 自动化测试、E3 专家评审、E4 用户测试、E5 线上数据。
2. **采集证据**：记录原始路径、样本量、时间区间、环境、硬约束单测、Golden Case、性能、用户认可率、分享率、限制和反例。
3. **失败归因**：每个「未达失效判据」的假设，判断错在**数据 / 算法 / 交互**哪一层。
4. **判断充分性**：技术证据只能证明技术子结论，不能替代用户认可；证据不足时保持「验证中」并记录部分支持/反对。
5. **回写登记册**：仅在满足预设证据条件时更新为已证实/已推翻/需调整，并使用回写模板。
6. **输出下一步**：说明缺失证据、本 Phase 调整和是否触发 ADR 重议。

## 关键提醒

- 主观指标（认可率）有社会赞许偏差，务必配合客观子指标（硬约束、Golden Case）一起看。
- 结论要能回答「H3 失败到底因为数据错了、算法不够好、还是交互让用户没感受到」。
