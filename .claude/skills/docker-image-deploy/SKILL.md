# 本地构建与 Compose 镜像发布

## 输入与适用边界

从当前项目部署文档、配置和用户指令确定以下输入；已有信息不重复询问：

| 输入 | 内容 |
|---|---|
| 构建 | 本地源码目录、各服务 Dockerfile、构建上下文、构建参数、测试命令 |
| 平台 | 目标操作系统/CPU 架构、本地 Docker context 与 buildx builder |
| 仓库 | Registry、镜像名称、推送和拉取凭证的存储位置 |
| 目标 | SSH 连接方式、Compose 目录、项目名、服务名、入口端口/域名 |
| 持久状态 | 数据卷/绑定挂载、环境文件、运行配置、备份及数据库迁移策略 |
| 验收 | readiness、页面/API 核心流程、版本标识和回滚条件 |

不在技能中保存具体主机、账号、绝对项目路径、仓库地址或凭证。环境值从本轮输入取得，不从历史示例猜测。

遵循项目指令和当前会话授权。此技能不自动授权部署、清理或外部调用；已经获得的授权继续有效。缺少某项输入时先完成不依赖它的准备工作，再集中询问。

## 交付原则

- 本地构建 → 本地验证 → 推送仓库 → 服务器拉取 → Compose 更新 → 验收。
- 检查 Docker context/buildx builder 的实际位置，不能把远程构建伪装成本地构建。部署服务器不执行源码构建，也不接收源码压缩包、工作区或 `.git`。
- 宿主机仅保留部署配置、运行数据、凭证和备份。镜像内的必要运行代码属于制品；如要求连镜像内也没有解释型语言源码，需另行明确打包方式与限制。
- 不把密码、token、Key 放入命令参数、镜像层、构建参数或报告。优先使用凭证存储、stdin 和 BuildKit secret mount。只输出必要的脱敏检查结果，避免完整环境、完整 inspect/config 输出。
- 更新只作用于目标 Compose 项目和本次授权服务；不运行全局 prune、不默认执行 `down -v`，不删除活跃数据卷或同机其他业务。

## 执行流程

1. **盘点与登记。** 阅读项目工作规则和状态入口；核对只读 Git 状态、当前 Dockerfile/Compose、服务挂载与端口。按项目约定登记触碰文件。清理历史源码属于独立操作：先检查唯一数据、配置、密钥、挂载、符号链接和 Git 元数据，再按项目删除规则列清单执行。
2. **准备可复现构建。** 检查 `.dockerignore` 排除凭证、数据库、开发环境、依赖目录和缓存；确保没有排除构建必要文件。使用锁定依赖和项目规定的测试。记录 HEAD、工作区是否有改动以及构建输入身份；不能仅用 HEAD 代表含未提交改动的制品。
3. **本地构建与验证。** 按目标平台构建各服务，使用唯一 release tag。核对前端 API 地址、路径前缀、静态资源版本、容器启动命令和权限。执行适当的镜像 smoke test；本地测试数据与正式持久数据隔离。未通过时不推送发布。
4. **推送并锁定制品。** 推送用户指定仓库，读取远端 digest，核对目标架构。为 Compose 准备明确镜像引用，优先使用 digest；不覆盖已发布 tag。API 与迁移任务如使用同一代码，应引用同一制品。
5. **准备发布与恢复。** 核对服务器真实配置，生成只包含必要 Compose、反向代理等文件的上传清单，禁止打包整个源码目录。服务器 Compose 仅引用 `image:`，不使用 `build:`。保留服务器环境文件及持久挂载；保存旧配置与 digest，按本次变更范围完成并验证备份。确认数据库迁移兼容性和失败恢复边界。
6. **执行更新。** 服务器拉取已验证镜像，在既有项目名下更新指定服务；按项目迁移流程先迁移再启动依赖新 schema 的应用。配置预检避免回显秘密。失败时停止扩大变更，不反复重试破坏性动作；仅在数据库兼容且已有授权时回滚应用 digest，数据库恢复不得自动覆盖线上数据。
7. **部署验收。** 检查容器健康、迁移版本、readiness、入口路由与核心业务流程；验证身份隔离、刷新/失败恢复和第三方数据来源。真实外部 API 必须核对权限、预算、缓存和错误处理，不能把“Key 配置存在”当成调用通过。部署环境能力以实际证据为准，内部 HTTP 复测不等同于正式 HTTPS 验收。
8. **交付记录。** 更新项目账本，记录 tag/digest、构建来源、配置变更、验证结果、持久数据保留情况、回滚依据与未完成项。遵循项目 Git 操作约定；不因完成部署而自动提交或推送代码。

## 缺失条件

本地 Docker 不可用、仓库无权限或平台不支持时，保留已完成准备结果并报告具体阻塞，不擅自切换服务器构建。缺少域名时仅在用户同意下使用指定内部端口，并明确 HTTPS 尚未完成。发现路径指向活跃数据或其他业务时停止相关清理，继续不依赖清理的构建和验证。
