# 求解器改动规则

**适用**：任何修改 `求解器 / 约束 / 聚类 / 时间窗 / 体力均衡 / 锚点 / OD 衔接` 逻辑的改动。

1. **必须附带对应约束单测**：新增或修改一条约束 → 新增或修改至少一条单元测试（见 [docs/test/](../../docs/test/README.md)）。
2. **必须跑 Golden Case 回归**：算法改动必须跑通 [docs/test/](../../docs/test/README.md) 中定义的 Golden Cases，不得使既有 Golden Case 失败。
3. **硬约束 100% 是底线**：硬约束违反数必须为 0 才能合并，不满足则回退重排。
4. **改动目标函数必须写 ADR**：任何改变求解「优化目标」的改动，属于架构决策，须记入 [docs/decisions/](../../docs/decisions/)。
5. **大模型不得参与求解**：求解器是确定性引擎，LLM 只负责解释生成，不得让 LLM 参与排程决策。
6. **体力是软约束**：不得以 3/5/8 星预算硬拦行程；恢复硬上限必须新写 ADR。
7. **不得静默丢弃**：未排入景点必须返回结构化原因；闭馆/天气不可用时先尝试跨天重分配。
8. **权威来源冲突即停工**：按 [Gate 规范](../../docs/process/gates.md) 报告冲突，不得用 Spike 或旧 skill 覆盖 Accepted ADR。
