# 数据质量门禁规则

**适用**：任何景点/餐饮/酒店等 POI 数据的采集、结构化、入库、字段改动。

1. **硬事实必须带来源与时间**：开放时间、闭馆日等字段必须有 `data_source` 与 `fetched_at`。
2. **未校准或冲突不得进求解器**：仅 `data_verified=1 && conflict=0` 的数据可进入输入集。
3. **入库前过校验**：开放时间/闭馆日/体力/类型必须满足 [docs/domain/开放时间数据规范.md](../../docs/domain/开放时间数据规范.md) 的校验规则。
4. **改动必须带校验测试**：新增/修改字段或校验规则 → 附带对应的数据校验测试。
5. **硬事实不得由 LLM 运行时生成**：开放时间/价格/闭馆日运行时一律读 DB。
6. **P1 使用最终时间模型**：使用多套 `time_rules`、`last_entry`、`close_days`、`is_always_open` 和闭馆例外；单套 open/close 仅属于历史 Spike 简化。
