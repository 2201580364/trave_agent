# 地点关系自动识别规则（O07）

## 1. 目的与边界

O07 用于识别可能导致重复选择、行程重叠或体验重复的地点关系，并在发布前要求完成裁决。关系记录由数据采集、归一化和候选目录构建程序生成；审核页面只负责展示证据和记录裁决，不提供任意手工新建关系入口。

当前实现是“规则/线索驱动”的识别管道，不是实时 AI 推理，也不是对任意城市自动完成空间拓扑推断。未被管道登记的关系不会因为打开 O07 页面而自动出现。候选导入会将目录中两端均已导入的关系线索幂等写入 `place_relations`；受控批量导入缺少另一端时会延迟到后续批次，不会创建孤立关系。

## 2. 识别对象

每条关系包含：起点地点、终点地点、关系类型、来源记录、关系审核状态、裁决状态和裁决说明。起点和终点使用归一后的 `place_id`，禁止使用名称作为主键，也禁止自指关系。

## 3. 归一与去重

1. **名称归一**：去除首尾空白、统一全角/半角标点和常见别名；保留原始名称在来源记录中。
2. **别名合并**：同一城市内，官方名称、官方英文名、已审核别名指向同一 `place_id`；仅名称相似不足以合并。
3. **实体去重**：同一实体的多来源记录进入同一地点修订版本；冲突内容保留并交由 O06 来源冲突裁决。
4. **关系去重**：数据库以 `(from_place_id, to_place_id, relation_type)` 唯一；同一事实的重复来源合并为证据，不重复生成关系行。
5. **方向约束**：`contains` 表示容器到被包含地点，`part_of` 表示地点到所属容器；二者不能用名称顺序代替语义方向。

## 4. 关系候选生成规则

### 4.1 `contains` / `part_of`

来源优先级为官方景区层级、官方地图/园区说明、候选目录显式父子关系。只有来源明确表达“位于、包含、组成、园内”等层级语义时才生成候选。生成一条 `contains` 时，可按同一事实生成反向 `part_of`，但必须保持方向语义一致。

### 4.2 `overlaps`

当两个地点的已核验几何范围相交、或官方说明明确存在空间重叠时生成。仅坐标相近、地址相同或名称包含不构成 `overlaps`。点状地点需要有明确的范围或官方重叠说明，不能用任意半径猜测。

### 4.3 `same_experience`

当两个地点共享同一演出、活动、观景体验或同一入场区域，且用户同时选择会产生明显重复体验时生成。证据应来自官方活动说明、场次说明或已审核的体验线索；不能仅凭类别相同生成。

### 4.4 关系线索的来源

当前管道支持：官方层级/活动说明、候选目录预登记线索、已审核几何拓扑线索、名称及别名归一结果、共享入场/演出区域线索。每条关系必须携带来源记录，来源失效时关系不得进入发布门禁的有效集合。

## 6. O07 裁决流程

1. 数据管道生成关系候选并写入 `place_relations`，初始为待审核、待裁决。
2. 数据编辑员在修订版本 O07 区域必须看到双方规范名称（不能只显示“当前地点/关联地点”）、关系方向、双方地点类型、关系类型的中文含义、识别依据、来源状态和证据定位；内部 ID 仅放在悬停追溯信息中。
3. 对真实关系选择“同意此地点关系”；对误报选择“驳回此地点关系”；暂时无法判断时保留“待处理”。三者分别映射为内部状态 `resolved`、`not_required`、`pending`。
4. 没有任何关系记录时，使用修订级“确认无关系”，而不是伪造一条关系行。
5. reviewer 逐项审核关系证据和裁决结果；修订审核通过后才可准备求解投影。

关系展示必须能让审核员直接读出完整句子。例如：

```text
西湖 → 断桥残雪
关系类型：包含（上级地点包含下级地点）
关系说明：西湖是范围/园区，包含断桥残雪
识别依据：西湖景区官方游览范围说明；来源：已登记官方页面
```

如果任一端名称无法从当前或历史 Revision 解析，界面应显示“待补充地点名称”并保留端点 ID 追溯，同时将该关系标记为需要数据编辑补齐名称，不得使用“当前地点 → 关联地点”这类无法裁决的泛化文案。

## 7. 来源冲突（O06）边界

O06 当前自动检查的是同一 `source_id` 下多条来源记录的内容指纹是否不一致。只有检测到多个不同内容指纹时才生成冲突并要求数据编辑员裁决；未检测到冲突时自动通过 O06，不再要求形式化的“无冲突确认”。不同来源对地址、坐标、开放时间等字段的差异，必须在 O04/O05 对具体证据进行人工比对；字段级自动冲突模型属于后续增强，不能用现有内容指纹检查替代。

## 8. 发布门禁

`overlaps` 或 `same_experience` 仍为待裁决时，阻断发布并返回 `OVERLAPPING_SELECTION_UNRESOLVED`。修订级关系检查仍为待检查且没有关系记录时，返回 `RELATION_REVIEW_REQUIRED`。已确认无关系、或所有有效关系已完成裁决，才可通过 O07；关系通过后仍需满足几何、访问点、开放时间、来源冲突和 reviewer 审核等其他门禁。

## 9. 误识别与漏识别

误识别通过 O07 “确认非关系”关闭；漏识别不能由审核员随意补录关系，应回到数据管道补充来源线索并生成新修订版本。这样可以保证关系可重复构建、来源可审计、发布快照可复现。

## 10. 后续增强

后续可增加真实几何库拓扑相交、别名词典、官方层级解析、关系置信度分层和离线人工补录工具。增强算法必须输出来源、规则版本和置信度，并继续接受 O07 人工裁决；不得绕过发布门禁。
