## 核心场景

以浙江省博物馆孤山馆区为例，普通周规则为周二至周日 09:00–17:00、16:30 最晚入馆，固定闭馆日为周一。选择年度中国大陆法定节假日历并勾选闭馆顺延后，系统生成：

- 节假日日期的 `open_override`；
- 每个连续节假日范围结束后自然日的 `closed`；
- 所有记录均为 `candidate`，需要 reviewer 逐项通过。

已发布运行时会将已核验的两类日期例外分别映射为 `open_on_dates` 和 `closed_on_dates`，周闭馆仍由 `close_days` 提供，保持 O05/求解器契约兼容。

补充人工验收修正后，节假日生成器只展开与固定闭馆星期真实冲突的日期；同一天只允许一条有效日期例外，历史异常重叠数据按“临时关闭优先”解析。管理端在日历加载失败时提供明确错误与重试入口，不再只显示不可解释的灰色按钮。

## 422 缺陷复现与修复

正式接口此前返回：

```json
{"error":{"code":"domain_validation_failed","message":"unknown place evidence action"}}
```

根因不是节假日历、来源或开放时间输入不合法，而是批量生成成功前写审计事件 `PLACE_HOLIDAY_EXCEPTIONS_GENERATED` 时，审计目标解析只支持 `DATE_EXCEPTION`，没有支持 `HOLIDAY_EXCEPTIONS`。现已将批量动作映射到 `place_date_exception`，并新增 HTTP 回归验证生成结果和审计目标类型。

使用正式 12 条数据数据库的临时副本 `.tmp/holiday-repro.db` 重新执行真实管理员登录与 POST 请求，返回 `HTTP 200`，修订版本正常递增；该验证没有写入 `.local/research.db`，临时 API 已停止。

## 管理端视觉优化

- Revision 顶部改为地点业务摘要和四项状态卡，内部编号移入折叠技术信息。
- O05 拆分为常规规则、固定闭馆、日期例外三个清晰区块。
- 指定日期预览改为紧凑工具条，常驻长说明改为悬停提示或区块副标题。
- 节假日生成弹窗按生成依据、开放时间分组；桌面端两列/三列，移动端自动单列。
- 单日例外按类型动态展示；临时关闭不显示时间，开放覆盖和场次覆盖要求完整时间。
- O05 各表格操作列统一固定在最右侧；发布准备只优先展示三项，其余折叠。
