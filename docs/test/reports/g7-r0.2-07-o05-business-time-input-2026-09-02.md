# G7-R0.2-07 O05 业务时间录入验收记录

更新时间：2026-09-02  
产品里程碑：M1 后段  
管理侧阶段：Gate 7 / OM1

## 变更口径

O05 周规则、固定场次和日期例外的管理端录入不再要求审核员填写分钟数。页面使用 `HH:mm` 输入，并在开始、结束、最晚入园字段旁提供“次日”勾选。数据库和 API 继续使用分钟数，不新增字符串时间字段，也不改变求解器契约。

示例：

```text
开始 23:00
结束 02:00 + 勾选“次日”
→ API end_minute = 1560
```

## 已完成验证

- `09:30` 转换为 `570`。
- `02:00 + 次日` 转换为 `1560`。
- `23:00 → 02:00` 未勾选“次日”时被客户端拒绝，并提示勾选次日。
- 最晚入园时间超过结束时间时被客户端拒绝。
- 已有分钟数据编辑时会自动显示为 `HH:mm`，大于等于 `1440` 的值自动勾选“次日”。
- O05 表格和指定日期解析预览使用“次日 HH:mm”展示，不再直接显示原始分钟数。
- 后端全量 pytest 通过。
- admin-web Vitest `8 个测试文件 / 34 个测试通过`。
- TypeScript typecheck 和 production build 通过。

## 兼容性结论

本次仅改变管理端输入与展示层。`PlaceTimeRule`、`PlaceDateException`、HTTP 请求字段 `start_minute/end_minute/last_entry_minute` 及求解器解析逻辑保持不变，因此普通时段、跨午夜场次和既有发布快照均保持兼容。

## 后续

需要在站内浏览器登录后打开 O05 新增/编辑弹窗，确认 `HH:mm` 控件与“次日”勾选的视觉布局；如要验证真实写入，应使用专门的 candidate 测试修订并确认后再提交，避免污染正式人工审核数据。
