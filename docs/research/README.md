# 用户研究

> G1 阶段计划。项目已经进入 M1 Gate 7 准备，但仓库尚无可回溯的真实访谈纪要和结论，因此 G1 存在证据补课债务，不能追溯伪造为已完成。M1 最终决策前完成 8–10 名目标用户发现研究，重点校准 H4、目标画像、AI 信任门槛和大交通决策顺序；该研究不自动进入 H3 `n>=21` 的确认性分母。

## 内容

- 研究计划（样本量、招募标准、访谈提纲）
- 竞品体验日志（小红书/携程/马蜂窝/Google Trips 摩擦点地图）
- 访谈纪要
- 结论（用户旅程地图、痛点优先级、JTBD、核心画像）
- **对 assumptions.md 的修订结果**

## 关键研究问题（摘自产品文档 11.3）

1. 做攻略的真实流程？各阶段耗时与最痛点？
2. 「选择焦虑」vs「信息碎片化」，哪个更大？
3. 什么情况下放弃自排行程改用现成攻略/跟团？
4. 对「AI 排行程」的信任门槛在哪？
5. 三个行程模式是否覆盖自述旅行风格？
6. 是否愿付费？心理价位与模式？
7. 大交通决策流程：先订票还是先做攻略？

## 结论如何影响产品（摘自产品文档 11.4）

| 发现 | 调整 |
|---|---|
| 选择焦虑比排程逻辑更大 | M2 对比/舍弃前置，M1 加同质化标记 |
| 对 AI 信任度低 | M1 强化可解释性，每步附理由 |
| 节奏提示不能让用户理解体力影响 | 调整「紧凑/适中/悠闲」解释和分天均衡提示；真实疲劳证据支持前不恢复硬上限 |
| 先订票再做攻略是主流 | M1 大交通前置为必填 |

## Gate 7 续接

M1 工程纵向切片完成后的真实专家/用户验证不在本目录虚构访谈纪要。统一方案和工具见：

- `docs/test/gate7-validation-plan.md`；
- `docs/test/gate7-expert-review-form.md`；
- `docs/test/gate7-user-test-script.md`；
- `docs/test/gate7-protocol-v1.json`；
- `docs/test/gate7-data-deployment-readiness-plan.md`；
- `docs/test/gate7-research-environment.md`。

真实证据收集前必须完成杭州研究数据、受控服务器 H5 和内部 dry run，并生成状态为 `locked` 的研究环境 manifest；当前 7 个路线点只用于技术回归，微信小程序正式上线不是 G7-R1 前置条件。杭州候选地点、网红区域和公开攻略来源由 AI 协作开发方自主检索、筛选、获取、登记并交叉验证，用户无需提供清单；只有付费、登录、授权或受限制来源才请求追加授权。Evidence 通过环境 ID 和 manifest SHA-256 绑定准确代码、数据、求解契约、数据库迁移和前端构建。原始联系方式、录音、屏幕录像和精确私人行程保存于受控研究空间，不进入 Git；仓库只接受去标识聚合报告、protocol/environment hash、样本区间、限制、反例和对 `docs/assumptions.md` 的结论回写。

G1 发现研究与 Gate 7 H3/H11 验证是两种不同证据：前者回答“用户的问题和优先级是否成立”，后者回答“当前 M1 方案是否被接受”。如复用参与者，必须在研究开始前明确协议、问题顺序和样本归属，不能把一份回答重复计入多个结论。
