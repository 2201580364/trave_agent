# 开放时间数据规范

> **属「硬事实」规范——求解器时间窗约束、LLM 数据抽取、数据校验都以此为准。**
> 目的：统一开放时间/闭馆日/室内外的编码格式，让「硬约束 100% 通过」建立在**数据正确**之上。

## 字段定义

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `open_time` | TIME | `HH:MM:SS` | 开放开始（未开放的户外点可用 06:00:00 近似，标注来源） |
| `close_time` | TIME | `HH:MM:SS` | 开放结束 |
| `close_day` | TINYINT | `0`=无闭馆；`1–7`=周一..周日 | **关键硬约束字段**，录错直接产生「周一排闭馆博物馆」事故 |
| `is_indoor` | TINYINT | `0`=室外；`1`=室内 | 天气适配（极端天气硬约束排除室外） |
| `suggested_duration` | INT | 分钟，> 0 | 建议游览时长 |
| `data_source` | VARCHAR | `gaode`/`baidu_baike`/`ctrip`/`manual` | 数据来源 |
| `data_verified` | TINYINT | `0`=未校准；`1`=已人工校准 | 数据质量门禁标记 |

## 校验规则（数据入库前必须全部通过）

1. `close_time > open_time`（跨午夜营业如演出，用「结束时间 + 1440 分钟」内部表示，导出时还原）。
2. `close_day` ∈ `{0,1,2,3,4,5,6,7}`。
3. `suggested_duration > 0` 且 `≤ close_time - open_time`（游览时长不得超出营业时长，跨午夜营业除外）。
4. `energy_level` ∈ `{1,2,3,4,5}`（见 [体力消耗标准.md](体力消耗标准.md)）。
5. `category` ∈ 9 类枚举（见 [景点类型体系.md](景点类型体系.md)）。
6. `lat`/`lng` 在合理经纬度范围内（中国境内）。
7. **每个字段都要有 `data_source`**；`data_verified=1` 之前不得进入求解器输入集。

## 求解器时间窗映射

- 求解器内部统一用「当天 0 点起的分钟数」表示时间：`open_min = open_time 转分钟`，`close_min = close_time 转分钟`。
- 到达时间 `arrival < open_min` → 视为「等开门」，`arrival` 推到 `open_min`。
- 离开时间 `arrival + duration > close_min` → **该景点当前天不可排**（硬约束违反）。
- `close_day == 当天 weekday` → **该景点当天不可排**（硬约束违反）。

## LLM 抽取边界

- LLM 可**抽取**开放时间/闭馆日作为候选，但**必须**经上述校验 + 人工抽检（`data_verified`）后才能入库。
- LLM **不得**在运行时直接生成开放时间/价格/闭馆日——运行时一律从结构化 DB 读取。
