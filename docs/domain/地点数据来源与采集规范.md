# 地点数据来源与采集规范

- 文档版本：V1.0
- 日期：2026-08-29
- 阶段：G7-R0.2-02
- 上游：ADR-0018、开放时间数据规范、Gate 7 数据与部署准备计划
- 机器资产：`data/governance/hangzhou-source-registry-v1.json`、`data/governance/place-collection-field-dictionary-v1.json`

## 1. 目的与边界

本规范回答四个问题：

1. 哪个来源可以被项目使用；
2. 允许通过什么方式获取；
3. 该来源允许提供哪些字段；
4. 数据能进入 staging，还是具备进入 published 审核链的资格。

来源公开可见、HTTP 返回 200、搜索引擎可找到、robots.txt 缺失或 LLM 能阅读，都不等于项目获得批量采集、复制、缓存或再发布授权。本规范是工程风险控制，不是法律意见；来源条款、合同或法律要求更严格时，以更严格要求为准。

## 2. Fail-closed 决策状态

| 状态 | 可进入 staging | 可直接作为 published 事实来源 | 处理 |
|---|---:|---:|---|
| `approved` | 是 | 是，但仍需字段审核和发布门禁 | 按允许字段、方式、配额和归属要求使用 |
| `conditional` | 是 | 否 | 满足条件并登记具体子来源后，生成新 registry 版本 |
| `pending_review` | 否 | 否 | 不采集；只保留非敏感候选 URL 和待办 |
| `prohibited` | 否 | 否 | 拒绝采集；只有新合同、官方 API 或书面授权触发重议 |

`conditional` 不能由采集脚本自行解释为“差不多可用”。当前政府门户和开放数据门户均保持 conditional：它们可提供候选和 staging 事实，但具体场馆页面、数据集许可和字段仍要逐项登记。

| `hangzhou-open-data-portal` | 杭州市数据开放平台 | conditional | 发现候选数据集 | 每个数据集单独审查许可、字段、归属和更新频率 |

批准只针对 registry 的 `allowed_fields + collection_modes + conditions`，不是对整个网站、全部 API 或未来新增产品用途的无限授权。

## 4. 排除清单

R0.2 首版默认禁止对以下来源执行批量页面采集：

- 小红书、抖音、微信公众号等社交 UGC 页面；
- 大众点评、携程、Trip.com、马蜂窝等 OTA/评论页面。

禁止内容包括：

- 用户昵称、账号、头像、联系方式和互动关系；
- 评论、帖子、聊天或攻略全文；
- 未授权图片、视频和页面副本；
- Cookie、token、验证码和绕过反爬的凭证；
- 实时价格或库存页面副本；
- 无法说明来源、窗口和采集时间的“网红指数”。

允许的重议触发条件只有：官方 API、联盟合同、书面授权、逐项用户内容授权，且必须先完成版权、隐私、保留期、归属、缓存、再分发和内容治理评审。

## 5. 采集字段字典

机器字典当前登记 58 个叶子字段，分为五类：

| fact_class | 例 | 发布要求 |
|---|---|---|
| `provenance` | 来源记录、URL、观察时间、内容哈希、Provider、版本 | 必须可追溯，不得含凭证 |
| `hard_fact` | 名称、地址、几何、访问点坐标、开放规则 | human_verified，冲突为 0 |
| `reviewed_attribute` | 类型、建议时长、体力、室内外、适合时段、地点关系 | 使用领域枚举和人工审核，不冒充硬事实 |
| `soft_signal` | 趋势分数、观察窗口、理由码 | 多来源人工综合、随时间衰减、不决定必选 |
| `provider_fact` | 高德 OD、和风天气 | Provider 校验、版本、抓取时间和合同限制完整 |

所有字段统一设置 `pii_allowed=false`。字典没有评论全文、用户身份、媒体二进制、Cookie、token、票务库存副本等字段，因此采集器不能以“暂存”为由写入这些内容。

## 6. 字段级授权

每次写入前使用四元组判定：

```text
source_id + field_id + collection_mode + target_stage
```

同时满足以下条件才允许：

1. `source_id` 已登记；
2. 来源不是 pending/prohibited；
3. `collection_mode` 同时被来源和字段允许；
4. `field_id` 位于来源 allowlist；
5. 来源角色符合字段要求；
6. 目标为 published 时，来源必须为 approved；
7. 后续 Place/Revision/访问点/时间规则/冲突/投影门禁仍然通过。

稳定拒绝码：

```text
SOURCE_NOT_REGISTERED
FIELD_NOT_REGISTERED
SOURCE_PROHIBITED
SOURCE_REVIEW_PENDING
COLLECTION_MODE_NOT_ALLOWED
COLLECTION_MODE_NOT_ALLOWED_FOR_FIELD
FIELD_NOT_ALLOWED_FOR_SOURCE
SOURCE_ROLE_NOT_ALLOWED_FOR_FIELD
CONDITIONAL_SOURCE_STAGING_ONLY
```

数据采集成功、HTTP 200、POI 命中、数量达标或人工“看起来正确”，均不能覆盖拒绝码。

## 7. 原始内容与凭证

| 内容 | Git | staging | published |
|---|---:|---:|---:|
| 来源 URL、时间、状态、哈希 | 允许 | 允许 | 允许作为审计元数据 |
| API Key、专属 Host 中的秘密部分、Cookie、token | 禁止 | 仅环境/Secret，不进入数据记录 | 禁止 |
| 政府/官方页面全文 | 不保存 | 默认不保存；必要时受控短期缓存并遵守来源条件 | 禁止 |
| Provider 原始响应 | 不提交 | 按合同和 TTL 受控缓存 | 仅结构化允许字段和哈希 |
| 评论、帖子、图片、视频 | 禁止 | 未授权时禁止 | 禁止 |
| 允许的结构化事实 | 允许版本化资产 | 允许 | 通过完整发布门禁后允许 |

日志只记录 `source_id`、字段、状态、reason code、时间、request ID 和非敏感摘要；不得打印凭证或带凭证的完整请求。

## 8. 版本与审计

- registry 和 field dictionary 使用规范化 JSON SHA-256；
- 每个采集批次绑定准确 registry/dictionary ID 与哈希；
- 已进入 published snapshot 或研究 environment 的版本不可原地修改；
- 来源条款、许可、允许字段、采集方式或归属要求变化时创建新版本；
- `next_review_on` 到期、HTTP 失效、条款 hash 变化或 Provider 合同变更时暂停新增采集，重新评审；
- 具体数据集、场馆、景区、攻略页面在 R0.2-04/R0.2-05 逐个登记，不能继承门户的无限授权。

## 9. Chrome 复核状态

2026-08-29 已按用户要求连接用户指定的 Google Chrome 可用实例，并完成首批 5 个来源的实际页面复核；浏览器选择结果明确为 Chrome，未切换到 Edge。复核时未登录第三方账号、未提交表单、未调用或展示 API Key，也未保存第三方页面副本或媒体。

Chrome 可见证据：

- 杭州文旅站点标题为“首页”，页眉为“杭州市文化广电旅游局”，页脚主办主体同为杭州市文化广电旅游局；
- 西湖管委会站点标题为“杭州西湖风景名胜区管委会”，页脚主办单位为杭州西湖风景名胜区管理委员会；“我想游”栏目可见西湖概况、活动和西湖十景条目；
- 杭州市数据开放平台标题和页眉主体一致，页脚显示由中共杭州市委、杭州市人民政府主办；点击“通用协议”后在 Chrome 新标签页打开 4 页《数据开放授权许可使用协议》PDF；
- 高德页面标题为“概述-Web服务 API | 高德地图API”，正文明确 Web 服务通过 HTTP 接口提供地理数据服务、使用前需申请应用 Key，并链接 API 使用条款；
- 和风页面标题为“服务条款 | 条款 | 和风天气开发者服务”，正文明确使用平台需要同意开发者许可协议、隐私政策和免责声明。

处理原则：

- 高德和和风依据官方 HTTPS 文档、条款页面、内容哈希和既有真实 API 联调证据登记为 approved；
- 三个政府/开放数据入口的浏览器复核状态更新为 `reviewed`，但来源决策仍为 conditional，只允许在已登记字段和方式内进入 staging；
- 页面可见、站点主体明确或存在门户级许可协议，仍不等于获得站点级批量遍历、整页复制或任意数据集再发布授权；
- 未稳定访问或未完成条款核验的其他候选来源不进入 registry 的允许清单；
- 具体场馆页面和开放数据集仍须在 R0.2-04/R0.2-05 逐项登记；若后续条款或页面语义与当前登记冲突，立即停止对应采集并创建新 registry 版本。

## 10. 执行与测试

```powershell
py -3.12 -m pytest tests/data_governance/test_source_registry.py -q
```
