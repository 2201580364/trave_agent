# ADR-0015：固定晚间活动前的单日间节点下午展开

- **状态**：已接受
- **日期**：2026-08-27
- **决策者**：产品 + 工程
- **关联假设**：H3、H7
- **前置**：ADR-0004、ADR-0009、ADR-0010、ADR-0011、ADR-0013

## 背景

ADR-0010 的 `DAY_SPREAD` 只定义了“两个及以上普通日间节点”的渐进式展开，并把单次额外延后限制为 60 分钟。该规则能避免多节点行程在改变既有顺序后产生新的 OD 或时间窗风险，但没有覆盖“一天只有一个普通日间节点和一个固定晚间节点”的真实场景。

7 个杭州路线点完成人工审核并使用新坐标重建 42/42 严格高德有向 OD 后，稳定分天将“西湖湖滨”和 19:30 的“西湖音乐喷泉表演”分在同一天。原实现只把西湖湖滨扩展到建议时长，仍从 09:00 开始：

```text
西湖湖滨：09:00–11:30
午餐：11:30–12:30
晚餐：17:52–19:22
音乐喷泉：19:30–19:50
```

12:30–17:52 形成约 5 小时 22 分钟无解释空档。硬约束和景点守恒虽然通过，但该结果不满足 H3 对“行程合理”的要求，也违反产品已经接受的“避免景点集中在上午而下午无安排”原则。

单日间节点没有日间节点之间的顺序或 OD 需要保护，继续套用多节点的 60 分钟移动上限无法解决该反例。因此需要扩展 `DAY_SPREAD` 语义，但不能削弱 C1/C2/C4/C5/C6，也不能为填满下午牺牲午餐、晚餐或固定场次。

## 决策

### D1 单日间节点只在存在固定晚间段时主动后移

当一天恰好有一个普通日间节点，并且同日存在已按 C2 排定的晚间段时，软精修可以在不改变节点顺序和 OD 的前提下后移该日间节点。

没有晚间段时，系统不进行这种跨数小时的主动后移，避免把用户本可自由使用的上午无依据地变成系统安排。

### D2 稳定目标仍为约 16:00 离开日间节点

精修顺序为：

1. 在窗口允许时，将日间节点从 C2 最低可玩时长扩展到发布建议时长；
2. 在 `11:30–14:00` 内保留至少 60 分钟可识别午餐空档，午餐可以位于首景点之前；
3. 以约 16:00 离开日间节点为稳定目标；
4. 保留“日间节点 → 晚间首节点”的真实 buffered OD；
5. 在晚间首节点前保留完整 90 分钟晚餐；
6. 晚间固定节点的到达时间和持续时间不前移、不后移。

### D3 多节点 60 分钟上限不适用于该单节点反例

`day_spread_max_delay_min=60` 继续约束两个及以上日间节点的渐进式局部调整。单日间节点没有日间内部顺序或新增 OD，允许为了覆盖下午移动超过 60 分钟，但仍受约 16:00 目标、午餐、完整晚餐、真实跨段 OD 和全部硬窗口共同限制。

本次没有修改 `day_spread_target_end_min=16:00`、午餐窗口、午餐时长、晚餐时长、交通缓冲或其他默认数值，因此参数版本不升级。

### D4 任何不安全候选都回退

以下任一条件不满足时，保留扩展后的原硬可行时序；若连时长扩展也不可行，则完整回退 OR-Tools 原结果：

- 景点开放时间或 `last_entry`；
- 首日到达、末日离开等 C4 锚点；
- 固定晚间节点 C2 时间窗；
- 真实跨段 OD 和 1.2 交通缓冲；
- 60 分钟午餐空档；
- 90 分钟完整晚餐；
- 最终 C1/C2/C4/C5/C6 全量校验。

晚餐本身仍是软约束；本规则只在完整晚餐本来可保留时执行积极后移，不把无法安排完整晚餐升级为硬失败。

### D5 版本组合

请求结构、结果结构、硬约束和默认数值参数均未改变：

```text
solver contract    = solver-p1-v2
result schema      = trip-result-v2
parameter version  = parameters-p1-2026-08-26
```

`DAY_SPREAD` 的适用范围和回退语义发生变化，因此约束版本升级为：

```text
constraint version = constraints-p1-v5
```

历史 `constraints-p1-v1/v2/v3/v4` Revision 不迁移、不覆盖、不原地重算。新生成 Revision 使用 V5，并继续通过完整回放键区分结果。

## 验收

新增 `HZ-GC-08` 和对应 Step 3 单元测试：

```text
Given 西湖湖滨建议游览 150min
And 西湖湖滨 → 音乐喷泉为高德 walking 386m / 6min
And 音乐喷泉固定为 19:30–19:50
When 生成当天行程
Then 午餐 11:30–14:00 内至少保留 60min
And 西湖湖滨稳定在约 13:30–16:00
And 晚餐完整保留 90min
And 音乐喷泉仍在 19:30
And C1/C2/C4/C5/C6 违反数为 0
And 重复求解结果一致
```

同时必须验证 `last_entry` 较早时不后移，并重新运行全量测试、Golden、降级、接近度、数据校验和性能门禁。

## 后果

- 单景点宽松日不再因为固定晚间场次而把全部日间活动压在上午；
- 午餐可以自然位于首景点之前，下午由真实景点覆盖，晚餐和固定表演不受破坏；
- 该规则仍是确定性软精修，不引入随机性、额外地图请求、新 OD 或第三方依赖；
- 它不要求机械填满全天，也不替代后续对自由活动、休息和具体餐厅节点的显式建模。

## 何时重新评审

- Gate 7 用户或专家证据表明单景点更应默认安排上午；
- 用户显式留白、锁定时段或自由活动节点进入 M1/M2 求解输入；
- 午餐从结果空档派生升级为正式求解节点；
- 多个固定晚间节点、餐厅节点或酒店起终点要求联合优化；
- 16:00 稳定目标在其他城市或季节持续产生不合理结果。
