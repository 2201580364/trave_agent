# ADR-0028：可解释行程评审与有界反馈优化

- 状态：已接受（2026-09-18；M1 采用固定版本专家规则与有界优化，反馈自动调权后置）
- 日期：2026-09-18
- 关联：H2/H3/H7、C1/C2/C4/C5/C6、S1/S2、R0.2-06。
- 前置：ADR-0004、ADR-0026、ADR-0027。

## 背景

真实十景点三日回放表明：主搜索漏计初始分开的近邻，后置单点吸附不能探索联合交换；错误发布时长影响负载，页面取整掩盖异常；硬约束通过不等于体验合理。逐对多模式OD采集与搜索需分别治理，不能用多轮整单重算放大等待。证据见[复审报告](../test/reports/solver-real-od-review-20260918.md)。

## 决策

采用确定性求解、独立硬校验、可解释评分和有界候选调整。完整规则、公式、权重、证据边界和验收见[设计方案](../product/行程评审评分与有界优化方案.md)，本记录不复制参数。

1. 物理硬约束与数据门禁不可补偿；守恒、安排覆盖独立于体验百分制，禁止删点或缩时刷分。
2. 所有选中近邻统一进入评审，候选包括组移动、交换和联合操作；首次自动生成不因偏离种子而扣分。
3. 体验按游线、游览价值、节奏、衔接、餐休、体力与明确偏好分项评价；未知事实独立记录，LLM不参与计分和排程。
4. 替代 ADR-0027 整段比较元组及一律下午展开偏好，采用覆盖→严重软缺口→加权体验损失→交通/用户编辑稳定性的比较；初始天内路由仍可用最小交通生成种子。
5. 协调器保留最佳可行方案和少量差异化候选，固定数据与评分版本，去重、轮数/路由预算、无改善停止与墙钟看门狗共同终止；不宣称全局最优。
6. 所有迭代复用同一真实OD快照，仅重算受影响日期；记录阶段耗时与改善轨迹。未来反馈仅离线校准软偏好，不能在线放松硬约束或自动改事实。

运行版本为 `solver-p1-v2 / trip-result-v2 / constraints-p1-v9 / parameters-p1-2026-09-18a`，评分策略 `expert-itinerary-review-v1`，默认权重 `expert-default-2026-09-18`。结果 schema 只增加向后兼容的评审和优化摘要，历史 Revision 不迁移、不覆盖、不原地重算。

用户反馈驱动的权重调整不属于 M1 在线能力。M1 只提供离线候选校准接口：默认至少 200 条反馈、80 名独立用户，单维权重一次最多变化 3 个百分点，并要求 Golden、恶意/边界样例、专家回放和人工批准全部通过。候选接口不能激活生产权重，生产切换必须另行版本化发布并可回滚。

## 替代方案与代价

- 仅修补现有分天：改动小，但难解释和系统评估餐休、空档、稳健性。
- 纯评分枚举：候选空间过大、难保障硬约束，拒绝采用。
- 无界“评审打回重生成”：可能振荡、重复地图调用和失控耗时，拒绝采用。
- 有界混合：保留现有确定性引擎，代价是评分参数、候选审计和回归维护增加；以版本管理和独立专家评审控制偏差。

## 接受及重新评审条件

启用前完成设计中的指标、反刷分、终止、Golden、真实OD反例对照与本地浏览器验收，更新solver/API/参数契约。专家经验等价声明须另有真实盲评和用户证据，工程测试不能替代。

若权重小变化导致大幅退化、严重体验项持续出现、算法利用指标漏洞、性能预算无法满足或专家评审偏好未改善，重新评审规则与候选策略，不通过提高分数标签或隐瞒未排项规避。
