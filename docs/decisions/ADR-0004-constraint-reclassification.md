# ADR-0004：约束分级修订（硬约束收窄，体验归入软约束）

- **状态**：已接受
- **日期**：2026-08-21
- **决策者**：产品 + 工程
- **关联假设**：H1、H2、H3、H7
- **前置**：ADR-0001/0002/0003，G4 评审（solver-review + test-review）

## 背景与问题

G4 评审发现「硬约束 100% 通过」未被真正保证（4 个 P0 缺陷）。产品据此重新审视约束分级，结论：**硬约束应只保留「物理上能不能」**（闭馆、关门、赶不上交通、极端天气、物理可达），「玩得够不够、累不累」是体验，应归软约束。这既让硬约束更可测、可守，也更符合「不错」优先于「更好」的原则——不错 = 不违反物理底线。

## 决策

### D1 闭馆日支持多天

`close_day TINYINT`（单值）→ `close_days JSON`（如 `[1,2]` = 周一+周二闭馆）。约束 C1：`weekday ∈ close_days → 不可排`。

### D2 建议游览时长软阈值（60%）

建议时长不再要求「玩满 100%」。修订为硬窗口 + 软提示：

```
硬窗口：arrival ∈ [open, min(last_entry, close − 0.6 × suggested_duration)]
软提示：可玩比例 = (close − arrival)/suggested_duration，< 100% 时标注「实际可玩 X min」
```

- 阈值 60% 为可调参数；=1.0 退化为原严格版。
- 好处：15:30 到达、17:00 关门的 2h 景点（可玩 75%）会排入，而非整单丢弃。

### D3 体力从硬约束降级为软约束

体力不再硬拦，改为「**分天均衡偏好 + 输出提示**」：
- 分天时倾向把高体力景点分散到不同天（软偏好，不硬拦）。
- 输出标注「本日节奏偏紧 / 偏松」。
- **连带**：行程模式从「硬预算（8/5/3 星）」重新表述为「节奏参数集」（时长阈值、均衡强度、密度）。

## 修订后的硬/软约束分级

| 类型 | 编号 | 约束 |
|---|---|---|
| 硬 | C1 | 闭馆日（`close_days` 多天 + 节假日例外） |
| 硬 | C2 | 入园时间窗（`arrival ≤ min(last_entry, close − 0.6×duration)`） |
| 硬 | C4 | 时间锚点（Day1/DayN，含返程交通） |
| 硬 | C5 | 极端天气排除室外 |
| 硬 | C6 | 时间衔接（真实路网 OD） |
| 软 | S1 | 建议时长比例（≥60%，<100% 提示） |
| 软 | S2 | 体力均衡 + 节奏提示 |

## 影响

- **P0-1 自动消解**：体力不再是硬约束，无需 OR-Tools energy 硬维度，`rebalance` 不再需要保证体力收敛。
- **P0-4 纳入 C2**：`last_entry` 进入时间窗上界。
- **H1/H2 需改写**：H2「3/5/8 星日预算」语义从「硬上限」改为「节奏参数」，验证方式相应调整。
- **目标函数不变**：仍 `min Σ travel`；体力均衡在分天启发式里体现，不进目标函数。

## 何时推翻重议（触发条件）

1. **H2 验证发现「节奏提示」无法替代体力上限**（用户疲劳度偏差大）：考虑恢复轻量硬上限（如「每日体力 ≤ 预算 × 1.5」）。
2. **若 60% 时长阈值导致大量「半程游」负面反馈**：上调阈值或改为按景点类型差异化阈值（演出类可更严）。
