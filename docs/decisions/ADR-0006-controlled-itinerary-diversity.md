# ADR-0006：确定性底座上的受控行程多样性

- **状态**：已接受（实现延期，M1 保持稳定主方案）
- **日期**：2026-08-23
- **决策者**：产品 + 工程
- **关联假设**：H3（行程合理性与用户认可）
- **前置**：ADR-0003（目标函数）、ADR-0004（约束分级）、ADR-0005（求解审计）

## 背景与问题

当前求解器对相同输入产生稳定结果，有利于测试、故障复现、审计重放和保存后的行程一致性；
但如果用户选择相同的 7 个景点和 3 天时间时永远只能看到唯一方案，产品可能显得机械，
也无法呈现多条质量接近但节奏、分天或顺序不同的合理路线。

无设计的随机打乱同样不可接受：它可能增加交通、改变未排入数量、破坏固定场次，并使线上问题
无法重放。因此需要区分“不可解释的随机漂移”和“显式请求的受控多样性”。

## 决策

### D1 采用“确定性底座 + 显式多样性”

- 默认生成稳定主方案，M1 使用 `seed=0`；
- 系统重试、任务恢复、审计重放和读取已保存行程必须沿用原 seed；
- 只有用户显式执行“换一个方案”或选择新的软偏好时，才生成新候选；
- 不允许在普通刷新、网络重试或 worker 重试中偷偷改变行程。

稳定回放键为：

```text
input_snapshot_hash
+ data_snapshot_version
+ solver_version
+ constraint_version
+ parameter_version
+ random_seed
= 相同结构化输出
```

### D2 随机性不得影响硬事实和硬约束

`random_seed` 只能影响同分/近优候选的生成顺序、软目标轻微扰动和候选池最终选择；不得改变：

- C1/C2/C4/C5/C6 的判断；
- 数据门禁、开放时间、天气事实和 OD 数据；
- 景点守恒；
- 用户锁定项和固定场次；
- 最终硬约束复核；
- 未排入原因的真实性。

任何候选在展示前都必须重新通过 `SolverQualityReport`。

### D3 先生成候选池，再过滤和选择

禁止通过 `shuffle(input)` 直接制造差异。后续实现采用：

```text
稳定主方案
→ 使用显式 seed 生成多个可行候选
→ 硬约束与景点守恒过滤
→ 近优质量过滤
→ 相似方案去重
→ 按用户偏好/seed 选择
→ 最终独立复核与审计
```

候选质量向量至少包含：

```text
hard_constraint_violations
unplaced_count
total_travel_min
max_single_leg_travel_min
daily_energy_variance
daily_utilization_variance
tight_day_count
meal_status
```

使用字典序，不用一个难以解释的总加权分：

1. 硬约束违反数必须为 0；
2. 未排入数不得高于主方案；
3. 固定场次与锁定项必须完全命中；
4. 再比较交通、体力、节奏和多样性。

### D4 近优阈值是可版本化参数

初始候选准入条件：

```text
total_travel_min ≤ best_total_travel_min × 1.10
max_single_leg_travel_min ≤ best_max_single_leg × 1.15
```

`10%/15%` 是 M2 初始实验参数，不是永久业务真理；必须进入 `parameter_version`，并通过
Golden Cases、专家评审和用户测试校准。最佳交通为 0 时使用绝对分钟阈值，避免除零和无意义比例。

### D5 方案相似度用于去重，不作为硬约束

初始相似度定义：

```text
similarity =
  0.5 × day_assignment_similarity
+ 0.3 × adjacency_similarity
+ 0.2 × time_bucket_similarity
```

- `day_assignment_similarity`：景点落在相同日期的比例；
- `adjacency_similarity`：有向相邻景点边的重合比例；
- `time_bucket_similarity`：上午/下午/晚间桶相同的比例。

候选池初始去重阈值为 `similarity > 0.80`。权重和阈值同样进入参数版本，属于软策略；
不能因为无法达到差异阈值而返回更差或违反硬约束的行程。没有合格替代方案时应明确告知用户。

### D6 支持锁定语义，锁定优先于多样性

后续“换一个方案”至少支持以下锁定：

- 锁定整天；
- 锁定景点日期；
- 锁定上午/下午/晚间时段；
- 锁定固定场次；
- 锁定两个景点同日。

锁定项属于候选生成的不可变条件。若锁定组合不可行，返回结构化冲突，不得自行解锁。

### D7 API 与审计语义

后续 API 使用显式意图，而不是把 `regenerate` 同时表示重试和换方案：

```text
replay：沿用 seed，结果必须一致
alternative：新 seed，选择近优差异方案
```

每次候选选择至少审计：

```text
random_seed, parent_solve_run_id, variant_index,
candidate_count, accepted_candidate_count,
quality_vector, similarity_to_primary,
lock_snapshot_hash, selection_reason
```

已保存行程记录其 seed 和版本；以后读取不得重新求解替换原结果。

### D8 分阶段交付

- **M1/Gate 6**：保留 `seed=0` 稳定主方案，验证可回放；不引入随机行为；
- **M2 设计切片**：先实现质量向量、相似度和锁定模型，均为纯函数；
- **M2 候选生成**：增加显式 seed 和候选池，默认方案语义不变；
- **M2 产品接入**：上线“换一个方案”，并进行用户实验；
- 任一阶段不得绕过最终质量门禁。

## 测试与验收

实现受控多样性前必须具备以下自动化证据：

1. 同输入、同版本、同 seed 连续运行结果完全一致；
2. 不同 seed 至少产生两个通过相似度阈值的候选，否则明确无替代方案；
3. 所有候选 C1/C2/C4/C5/C6 违反数为 0；
4. 所有候选景点守恒，未排入数不劣于主方案；
5. 交通和最长单段不超过版本化近优阈值；
6. 锁定项、固定场次和用户时间锚点完全不变；
7. 每个 seed 可审计重放；
8. 候选不足、全部过差或锁定冲突时有结构化降级结果；
9. Golden Case 报告同时保存主方案、候选质量和相似度；
10. 用户实验区分“方案不同”与“方案更好”，不得只以点击换一换次数作为成功证据。

## 备选方案与权衡

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 永远唯一确定方案 | 最稳定、最易测试 | 产品机械，无法提供合理替代 | 保留为默认主方案，不作为唯一能力 |
| B. 每次随机打乱输入 | 实现简单、表面有变化 | 质量不可控、不可重放、可能破坏约束 | ❌ |
| C. 多目标随机搜索直接返回一个结果 | 可能产生差异 | 很难解释质量边界，回归不稳定 | ❌ M1 不采用 |
| D. 确定性主方案 + 受控近优候选池 | 稳定、可解释、可审计、可逐步实现 | 需质量向量、相似度、锁定和候选管理 | ✅ |

## 后果

- **正面**：稳定回放和用户多样性不再冲突；多样性具有质量上限和审计证据；可渐进实现。
- **代价**：M2 需要多次求解、候选去重、锁定模型和更多报告字段；响应时间和缓存设计需重评估。
- **技术债务**：当前求解器尚无候选池、相似度和锁定模型；API 的 `regenerate` 语义需要拆分。
- **兼容性**：默认 `seed=0` 行为保持不变，现有行程、Golden Cases 和审计记录无需迁移。

## 何时推翻重议（触发条件）

1. 用户测试显示多数用户只需要一个方案，且“换一个”使用率低于 10%，则降低实现优先级；
2. 近优候选生成使 P95 超过产品时限，评估离线预生成、缓存或减少候选数；
3. `10%/15%` 阈值导致用户明显认为替代方案更差，收紧并按旅行模式分层；
4. `0.80` 相似度仍产生大量“看起来一样”的方案，调整特征、权重或阈值；
5. 用户频繁要求保留局部安排，提前实现整天/景点锁定；
6. 多样性负面反馈主要来自数据或解释而非路线本身时，不扩张随机搜索，优先修数据/交互；
7. 求解器升级为多车辆/住宿联合优化时，重新评估候选生成位置和质量向量。

## 当前明确不做

- 不在 Gate 6 中改变当前默认求解结果；
- 不让 LLM 生成结构化行程候选；
- 不以随机数覆盖硬约束、固定场次或锁定；
- 不保证每次“换一个”一定有不同方案；
- 不在没有质量和相似度证据时上线该功能。
