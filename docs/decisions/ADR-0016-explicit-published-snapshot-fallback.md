# ADR-0016：正式快照显式回退与旧版本持续服务

- **状态**：已接受
- **日期**：2026-08-27
- **决策者**：产品 + 工程
- **关联假设**：H3
- **前置**：ADR-0005、ADR-0009、ADR-0011、ADR-0013、ADR-0014

## 背景

M1 生产请求只读取不可变 Published Solver Snapshot，第三方高德和和风网络调用仅发生在发布前。该边界保证了用户点击“生成行程”时不受第三方即时故障影响，但原生产组合根只接受一个 `TRAVEL_AGENT_PUBLISHED_SNAPSHOT_VERSION`：如果运维提前切换到一个缺失、损坏、仍为 candidate 或未通过门禁的新版本，进程会拒绝启动，已验证的旧快照也无法继续服务。

新快照失败时继续使用旧快照不能通过扫描目录、自动选择“最新文件”或放宽 published 门禁实现，否则会引入不可审计选择、误用 candidate 和版本漂移。

## 决策

### D1 当前版本保持显式选择

`TRAVEL_AGENT_PUBLISHED_SNAPSHOT_VERSION` 仍是生产进程的首选版本。生产组合根继续在启动时校验文件存在性、安全版本名、内容哈希、`status=published`、`human_verified` 坐标、真实天气、完整严格 OD、城市和数据版本一致性。

### D2 只允许显式、有顺序的已知良好回退版本

新增可选配置：

```dotenv
TRAVEL_AGENT_PUBLISHED_SNAPSHOT_FALLBACK_VERSIONS=<previous-v2>,<previous-v1>
```

组合根按当前版本、回退版本声明顺序逐一执行完全相同的 Published Snapshot 门禁，选择首个有效版本。不得扫描目录，不得按文件时间猜测，不得自动加载 candidate，也不得跳过城市、哈希、坐标、天气或 OD 校验。

### D3 回退必须可观测

发生回退时记录模块级 error 日志，包含请求版本和实际选中版本，不包含凭证、完整请求参数或私人数据。FastAPI `app.state` 暴露请求版本、选中版本和 `fallback_used`，供后续 readiness、部署检查和配额/快照状态接口消费。

### D4 所有候选均无效时继续 fail-fast

如果当前版本和所有显式回退版本都无效，生产组合根拒绝启动。持续服务只允许复用已通过完整门禁的旧 Published Snapshot，不能用近似 OD、审计天气或未审核坐标换取表面可用性。

## 影响

- 新快照构建或切换错误不再必然中断旧版本服务；
- TripRevision 继续保存实际选中的不可变数据版本，历史结果不原地重算；
- 当前实现解决单进程启动选择和显式旧版本回退，尚未替代多实例发布协调、跨机器缓存、集中配额看板或正式数据库发布表；
- 运维发布时必须保留至少一个经过回放的旧版本，并在确认新版本健康后再调整回退列表。

## 验证

- 当前版本有效时不使用回退；
- 当前版本缺失、损坏、candidate 或门禁失败，显式旧版本有效时继续启动；
- 当前与回退均无效时拒绝启动；
- 回退选择写入应用状态并记录脱敏日志；
- 现有 candidate、城市、哈希、坐标、天气和 OD 门禁测试继续通过。
