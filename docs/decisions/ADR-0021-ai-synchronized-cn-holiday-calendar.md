# ADR-0021：中国法定节假日历由 AI 辅助自动同步并经确定性门禁发布

状态：已接受（M1 / OM1 / Gate 7，待实现）

日期：2026-09-02

## 背景

ADR-0020 已确定：地点的“法定节假日开放、节后顺延闭馆”策略通过版本化年度日历展开为 O05 `PlaceDateException`，求解器继续消费稳定的日期例外契约。当前 2025、2026 日历仍是代码内置目录，管理端只有读取和选择能力；进入新年度时，如果开发人员没有修改代码并重新部署，系统不会出现对应年份。

用户明确要求年度法定节假日历不由业务人员逐项录入，而应由系统从中国政府官方公告自动获取、结构化、校验和同步。公告尚未发布时，系统应明确返回“该年度节假日安排尚未发布”，不能把网络失败、解析失败或非官方来源误判为尚未发布。

## 决策

1. M1/OM1 增加中国大陆单一地区的年度法定节假日历自动同步能力，管理端页面编号为 `O17`。
2. 管理端“同步节假日历”、后台周期任务和 AI Tool 必须调用同一个后端 `ChinaHolidayCalendarSyncService`，不得分别实现抓取、解析或写库逻辑。
3. AI 负责官方公告候选发现、页面/附件内容理解、结构化抽取和原文证据定位；来源白名单、年份匹配、日期范围、重叠、调休冲突、完整性、幂等、版本、审计和发布由确定性程序控制。
4. 最终事实只接受国务院、中国政府网及经 Source Registry 审核的中国政府官方来源。搜索引擎、新闻转载、百科、攻略和 AI 既有知识只能作为发现线索，不能作为发布依据。
5. 正常路径不要求人工录入或逐年人工审批：官方来源与全部强校验通过时，由应用服务自动发布不可变年度日历版本；AI 本身无权直接写 `published` 状态。
6. 任何来源、网络、解析或校验异常均 fail closed：不发布日历，不向 O05 暴露，并进入 `temporarily_unavailable` 或 `needs_attention`。只有官方发现流程成功且没有目标年份正式公告时，才能返回 `not_announced`。
7. 已发布日历不可原地修改。官方内容发生变化时创建 `v2` 等新版本，保留旧版本、来源快照、内容哈希和已物化的地点日期例外。
8. O05 只允许选择 `published` 年度日历；年度同步不改变既有 `PlaceDateException`、Projection 和求解器分钟值契约。
9. 数据模型可完整保存调休工作日，但 M1 O05 生成器只依据法定放假范围处理“固定闭馆日与节假日冲突”；调休工作日不自动改变地点开放状态。
10. 当前只支持中国大陆。多国家、多地区、通用公告解析平台和规模化城市数据刷新属于 OM2/M2。

## 状态语义

| 状态 | 含义 | 是否可供 O05 使用 |
|---|---|---:|
| `not_announced` | 官方来源可访问，但目标年度正式安排尚未发布 | 否 |
| `temporarily_unavailable` | 网络、TLS、超时或官方站点暂时不可访问 | 否 |
| `needs_attention` | 找到候选公告，但来源、解析或确定性校验未通过 | 否 |
| `published` | 官方来源、抽取、验证、版本和审计全部通过 | 是 |
| `up_to_date` | 已发布版本与当前官方内容哈希一致 | 是 |
| `superseded` | 已被同年度新版本替代，仅供历史回放 | 否 |

## 自动发布门禁

只有同时满足以下条件，应用服务才能自动发布：

- 来源域名和渠道已通过官方来源白名单；
- 公告标题、正文和请求年份一致；
- 原始 HTML/PDF/附件已保存内容哈希和观察时间；
- 每条节假日均能回溯到公告原文片段；
- 日期开始不晚于结束，节假日范围没有无法解释的重叠；
- 放假日期与调休工作日不冲突；
- 中国年度节日概念覆盖完整，允许中秋与国庆合并表达；
- 结构化载荷通过稳定 Schema 校验和规范化哈希计算；
- 相同来源内容重复同步保持幂等；
- 同年度内容变化创建新版本，不覆盖历史版本；
- 发布动作和同步过程均产生结构化审计事件。

## 取舍

- 接受使用 AI 适配非结构化政府公告，以减少年度人工维护和代码发版；同时拒绝让通用 AI 自由浏览后直接写生产事实。
- M1 只做中国大陆，降低来源、时区、节日语义和合规复杂度；通用化留到 M2。
- 正常路径自动发布，提高运营效率；异常路径仍保留人工查看入口，但人工只处理异常，不承担每年数据录入。
- 保留物化日期例外，使现有求解器、Projection、发布快照和历史行程可复现，不在本节点引入运行时节假日策略求值。

## 里程碑与优先级

- 管理侧：`OM1`；用户侧支撑：`M1`。
- 工作包：`G7-R0.2-09 中国法定节假日历自动同步与版本治理`。
- 初始实现优先级：`P1`；当产品允许规划的日期跨入无已发布日历的年份时自动升级为 `P0`。
- 应在当前 `G7-R0.2-08` O05 修复验收和提交后开始，并在 R0.3 受控部署前完成中国单一地区最小闭环。
- OM2/M2 再扩展多地区、多来源、通用抽取和批量地点影响修订。

## 验收条件

- 同步已有年份返回 `up_to_date`，不创建重复版本；
- 官方未发布下一年度公告时返回 `not_announced`，不创建伪日历；
- 网络失败返回 `temporarily_unavailable`，不得错误显示“尚未发布”；
- 找到公告但抽取或校验失败时返回 `needs_attention`，不进入 O05；
- 正常官方公告能自动生成并发布年度版本，O05 下拉可见；
- 官方内容哈希变化时创建新版本，旧版本及历史日期例外不变；
- 前端按钮、后台定时任务和 AI Tool 的结果、门禁和审计一致。
