# ADR-0022：地点数据采集进入 staging，关系线索与人工治理分离

- **状态**：已接受（设计决策，尚未实现）
- **日期**：2026-09-02
- **决策者**：产品 + 工程 + 数据治理
- **关联里程碑**：M1 后段、M2；OM1、OM2
- **关联工作包**：G7-R0.2-05-03、G7-R0.2-09、R0.3
- **关联文档**：[O18 地点数据采集与关系识别设计](../product/O18地点数据采集与关系识别设计.md)、[API 契约](../specs/api-contract.md)、[数据模型](../specs/data-model.md)

## 背景

项目需要从高德、景区官方页面和中国官方公告获取地点事实与关系线索。若采集器、爬虫或 AI 可以直接写入已核验或已发布数据，会绕过来源准入、字段级核验、冲突裁决、Revision 不可变和发布门禁，且失败重试可能产生重复或无法解释的事实。

## 决策

### D1：采集结果只能进入 staging

采集器、解析器、定时任务和 AI Tool 的输出统一进入 `CollectionBatch/CollectionResult` staging 层。只有确定性物化服务可以把合规结果转换为 candidate Revision、SourceRecord 和 RelationClue；任何采集 API 都不得直接设置 `human_verified` 或 `published`。

### D2：来源和字段采用 fail-closed 准入

每个批次固化 source registry、field dictionary、采集方式和目标阶段版本。缺少登记、许可不明、字段越权、凭证参数或来源条款变化时拒绝或暂停，不以“先采集再说”作为默认策略。

### D3：批次必须幂等、可暂停、可回放

批次使用 `operation_intent_id`、输入指纹、采集器/解析器版本和输入/输出哈希。相同载荷可重试并返回相同结果，不同载荷复用同 intent 必须拒绝。限流、网络、解析和 schema 变化分别记录原因码；回放不得重新访问来源，除非显式创建新批次。

### D4：关系识别产生线索，不直接成立关系

归一化和关系识别程序根据层级语义、官方关系说明、活动/入场区域和证据定位生成 RelationClue。名称相似或坐标接近只能产生关注线索。两端 Place 缺失时延迟导入；O07 由人工裁决、确认无关系并留下理由，未裁决关系不进入求解投影。

### D5：AI 只做证据辅助

AI 可以发现允许的官方来源、定位公告段落、提出结构化字段和关系候选；确定性校验服务负责来源、年份、日期、字段类型、幂等和状态转换。AI 不得判断“官方尚未发布”、猜测缺失事实、伪造证据或写入发布层。AI/定时主体必须在审计中与人工账号区分。

### D6：运行日志与业务审计分离

采集请求的诊断信息进入 ADR-0005 约定的每日分级日志并按月归档；批次、结果、物化、审核和失败原因进入追加式业务审计。日志清理不能删除治理事实，任何凭证、Cookie、Token、完整网页正文和未授权媒体均不得进入日志或数据库。

## 取舍

该方案增加 staging、批次和回放模型的实现成本，但可以保证自动采集失败不会污染正式目录，支持人工审核闭环和可解释重试。M1 只做杭州单城市、已登记来源和受控批次；多城市、多来源和 AI 扩展推迟到 M2/OM2。

## 验收门槛

1. 采集批次失败、部分失败、暂停和恢复均不改变 published 数据；
2. 同一 intent 重试不重复创建 SourceRecord、Revision 或 RelationClue；
3. 未登记来源、字段越权和 conditional 来源越级均被拒绝；
4. 关系线索可显示证据、规则版本和置信度，O07 裁决后才可进入发布门禁；
5. 审计可回答“谁/什么主体、何时、以哪个来源和解析器版本生成了什么结果”；
6. AI 或定时任务无法伪装成人工 reviewer 或 publisher。

## 后续重议条件

- 需要第三方数据供应商或跨租户采集时，重新评估来源许可、隔离和计费；
- 采集规模达到多城市高频调度时，评估独立 worker/队列和专用 staging 存储；
- AI 采纳率、误报率或审核成本达到 M2 目标后，再评估扩大 AI 自动化范围。
