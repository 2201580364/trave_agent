# ADR-0025：show 多场次求解与候选时间规则删除

- 状态：已接受（2026-09-10 用户明确要求，并确认由求解器选择可行场次）
- 关联：H3、C2、C4、C6；ADR-0018 D5/D7 的唯一固定场次限制由本 ADR 替代。

## 决策

1. show 的固定场次要求改为至少一条 active 场次；所有有效时间证据仍需来源与逐项审核。停用场次保留可见但不计入数量、准备度、日期解析、来源依赖及发布/求解校验。零有效场次不能审核或发布。
2. 已核验固定场次以独立结构进入投影，保留 session_id、source_record_id、开始/结束/最晚入场分钟、星期、日期范围、日期例外。发布投影固化这些字段并纳入 hash。单日 session_override 替代该日常规场次；closed 日期仍优先关闭，open_override 不生成不存在的场次；独立最晚入园规则随星期与有效日期限定继续约束入场，停用后不参与。
3. 同一 show 仍只对应一个 solver 节点。OR-Tools 对节点使用离散入场时刻域，结合真实 OD、首末日锚点选择可行场次，不把场次间隔合并成连续窗口，不按列表第一项预选。完整演出时长不可缩短，提前入场至演出结束的时间全部占用；同一入场时刻存在多个合格场次时以完整结束时间最早、再按 session_id 的稳定顺序选取。
4. 包含显式场次的日期使用联合天内求解，避免先解夜间段造成错失后续可行场次；此分支保留晚餐软块和可识别的午餐空档，暂不执行可能移动固定场次的 DAY_SPREAD/时长扩展。无显式场次的既有输入沿用原分段与时间填充。目标函数及硬约束集合不变，体力仍为软约束。
5. 约束版本升为 constraints-p1-v6。solver-p1-v2/trip-result-v2 增加可选 fixed_sessions 输入/selected_session 输出，不删除旧字段；无该字段的历史 JSON 可继续加载，历史 Revision 不改写。selected_session 保存选择的场次 ID、开始、结束、入场时刻；用户时间线与公开分享显示真实场次开始时间，公开分享不暴露内部场次 ID。
6. 候选入口对常规开放规则和固定场次提供删除与确认，不提供停用；审核入口保留停用，不提供删除。入口是 UI 行为边界，服务端授权依赖角色与 candidate 生命周期，不把 URL 查询参数作为安全凭证。其他候选证据面板也移除原停用按钮，本次不扩大为其他证据删除功能。
7. 时间规则删除仅限当前 candidate Revision 的对应行；独立 POST /place-revisions/{revision_id}/time-rules/{time_rule_id}/deletions 保留旧 DELETE 的停用兼容语义。删除要求编辑权限、expected_revision_version 和幂等 intent；修订资格重置、版本递增、PLACE_TIME_RULE_DELETED 审计与删除同事务。已发布/已核验修订和其他修订不受影响；操作审计保留，删除不是清理历史数据。

## 验证要求

- 零/一/多有效场次、停用与未核验证据分别检查。
- 星期、日期范围、日期覆盖、跨午夜、提前入场、完整演出时长和开闭馆约束保持有效。
- 首场赶不上而后续场次可行时，自动选择后续场次；全部场次不可行则明确未排入，不在间隔中安排。
- 两个 show 与普通景点混排，交通缺边和返程锚点不能绕过；同地点守恒且最终硬违反数为零。
- 候选删除与审核停用的 UI 区分，删除幂等/权限/版本/失败回滚，停用记录可见且不阻断其他有效证据。
- 求解器单测、Golden 回归、相关后端集成测试与前端测试、类型检查和构建通过。
