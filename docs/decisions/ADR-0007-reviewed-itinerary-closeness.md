# ADR-0007：可解释的评审行程接近度

- **状态**：已接受
- **日期**：2026-08-23
- **决策者**：产品 + 工程
- **关联假设**：H3（硬约束正确、行程合理并获得用户认可）
- **前置**：ADR-0004（约束分级）、ADR-0006（受控多样性）

## 背景与问题

硬约束零违反和景点守恒只能证明行程“物理上可执行”，不能证明分天、时段和游览顺序符合常见旅游经验。另一方面，只用一个总分或由 LLM 主观判断“像不像专家行程”，会隐藏具体差异、难以复现，也容易把公开攻略误称为专家意见。

因此 Gate 6 需要一个可执行、可解释、可版本化的接近度指标，比较求解结果与经过声明的评审基线。它是软质量回归证据，不是硬约束，也不能独立证明用户认可。

## 决策

### D1 硬门禁不可被接近度补偿

评估顺序固定为：

```text
景点守恒 + C1/C2/C4/C5/C6 零违反
→ 固定评审项全部命中
→ 软接近度达到版本化阈值
```

任一硬约束失败、景点缺失/重复或固定项失败时，基线门禁失败。再高的软分也不能补偿。

### D2 基线来源必须明确分级

基线必须声明以下来源之一：

- `DOMAIN_EXPERT`：由具备可核验资历的旅游规划专家评审；
- `HUMAN_REVIEWED`：由指定人员人工复核，但不声明专家资历；
- `PUBLIC_GUIDE_SYNTHESIS`：由公开攻略、官方开放信息综合构建。

公开攻略综合基线不得在文档、报告或产品中称为“专家金标”。当前杭州案例属于 `PUBLIC_GUIDE_SYNTHESIS`。

### D3 指标拆分并保留分项证据

MVP 指标包含固定项命中率、分天、上午/下午/晚间时段、指定景点同日、指定景点相邻及方向，以及加权综合接近度。

优选日期或时段命中记 `1.0`；明确允许但非优选的备选记 `0.7`；未命中或景点缺失记 `0`。没有对应期望的分项不参与加权，禁止用空基线获得满分。

初始软分权重为：

```text
day_assignment 0.35
time_bucket    0.25
same_day       0.20
adjacency      0.20
```

初始通过阈值为 `0.75`。权重、部分得分和阈值都是版本化实验参数，不是永久业务真理。

### D4 基线必须版本化、可追溯

每个基线至少保存 `baseline_id`、`baseline_version`、`provenance`、`source_refs` 和结构化期望。正式专家基线还应保存评审人/组织、评审日期、城市、旅行天数、旅行模式、输入景点集合、数据/OD/天气快照、求解器、约束和参数版本。来源或上下文变化时必须升级版本，不能静默覆盖历史基线。

### D5 不采用 LLM 自评分

LLM 可以帮助整理候选资料，但不能同时生成行程、定义金标并为自身输出打分。执行门禁只使用结构化期望和确定性纯函数；主观质量由独立人工评审和 G7 用户研究补充。

### D6 与受控多样性的关系

ADR-0006 的候选相似度用于候选去重；本 ADR 的评审接近度用于外部质量基线比较，两者目的不同。未来替代方案可以有结构差异，但仍必须通过相同硬门禁，并分别报告与评审基线的接近度。

## 测试与验收

自动化测试至少覆盖：精确命中、允许的非优选日期/时段、无向与有向邻接、固定项失败、硬门禁失败、景点缺失、重复期望、空基线和阈值边界。

Gate 6 报告必须保存来源类型、来源引用、硬门禁、固定项、各分项、逐期望诊断、综合分、阈值和最终结果。逐期望诊断至少包含相关景点、优选值、可接受值、实际值、得分、是否固定，以及 `preferred/acceptable/matched/missed/missing` 结果。杭州首个案例使用公开攻略综合来源，只构成技术回归证据。

## 后果

- **正面**：行程“合理性”从模糊印象变为可解释回归；算法变化能定位到分天、时段、同日或顺序；基线来源不会被夸大。
- **代价**：基线建设和版本维护需要人工成本；单一城市和单一来源容易过拟合；初始权重必须通过专家与用户数据校准。
- **不证明的内容**：技术接近度不证明真实专家一致认可，不证明用户满意度，也不证明公开攻略本身正确。

## 何时推翻或重议

1. 多位专家对同一场景分歧显著，单基线无法表达合理方案空间；
2. 接近度与用户认可、行后反馈长期低相关或负相关；
3. 求解器只针对少量基线优化，其他城市或旅行模式明显退化；
4. 来源、开放时间、OD、天气或旅行模式版本漂移；
5. 现有分项无法解释主要负面反馈；
6. 受控多样性上线后，合理替代方案因单一基线被系统性误判。
