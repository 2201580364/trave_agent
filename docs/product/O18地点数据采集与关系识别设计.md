## 1. 目标与边界

O18 负责把外部来源转化为可审计的 candidate 数据和关系线索，支撑地点审核、求解投影和受控发布。它不是一个“爬到什么就直接发布什么”的系统，也不是允许 AI 绕过人工治理的自动写库通道。

本设计覆盖：

1. 来源选择、采集授权和字段白名单；
2. API、官方网页和公告的受控采集；
3. 批次、限流、缓存、失败重试和暂停；
4. 名称/别名归一、实体去重和地点候选合并；
5. 开放时间、访问点、几何和地点关系线索抽取；
6. 候选 Revision、来源记录和 `place_relations` 导入；
7. O04/O05/O06/O07 审核衔接、审计和回放；
8. 采集变更、撤回、过期和重新送审。

不在 O18 自动完成：

- 将采集结果标记为 `human_verified` 或 `published`；
- 代替审核员做来源冲突裁决；
- 仅凭名称相似或坐标接近生成确定关系；
- 批量复制评论、账号、图片、视频或未授权页面全文；
- 用 LLM 生成开放时间、交通耗时或地点事实而没有来源证据；
- 在 M1 提前建设多城市、全站点、无限频率的通用爬虫平台。

## 3. 采集对象与来源边界

### 3.1 允许的采集对象

M1 只采集能够支撑地点候选或硬事实核验的结构化内容：

- 地点规范名称、别名、地址和行政区域；
- Provider POI ID 和候选坐标；
- 地点类型、区域归属和官方层级；
- 官方开放时间、固定场次、闭馆日和日期例外；
- 官方入口、出口、路线起终点和代表点；
- 官方关系说明、园区地图或活动场次说明；
- 来源 URL、观察时间、采集方式、内容哈希和版本信息。

### 3.2 来源准入

采集器每次写入前都验证：

```text
source_id + field_id + collection_mode + target_stage
```

验证结果必须符合 [地点数据来源与采集规范](../domain/地点数据来源与采集规范.md)。`approved` 来源可以进入 staging 并参与发布审核；`conditional` 来源只能进入 staging，不能直接作为 published 事实来源；`pending_review` 和 `prohibited` 直接拒绝。

当前杭州优先来源：高德 Web 服务、景区/政府官方页面、已登记的官方公告。社交平台和 OTA 评论页面不作为 M1 默认批量来源。

### 3.3 原始内容保留

默认不保存完整网页或 Provider 原始响应，只保存允许字段、来源指纹和必要的证据定位。短期缓存必须有 TTL、访问权限和来源条款依据；凭证、Cookie、Token、页面全文、评论正文和媒体不得进入数据库、Git、日志或报告。

## 4. 端到端流水线

```text
Source Registry
      ↓
采集任务配置
      ↓
Collector（API/官方页面/公告）
      ↓
原始响应校验与脱敏
      ↓
字段映射与结构化抽取
      ↓
名称归一 / 实体去重
      ↓
关系候选识别
      ↓
采集批次结果与差异报告
      ↓
Candidate Revision + SourceRecord + RelationClue
      ↓
O04/O05/O06/O07 人工审核
      ↓
Projection / Publication Gate
```

每一步都产生批次级审计信息。采集任务成功只代表结果已进入 staging，不代表事实正确、关系成立或地点可以发布。

## 5. 采集批次与状态机

### 5.1 批次状态

```text
draft → queued → running → paused → completed
                         ├→ partially_failed
                         ├→ failed
                         └→ cancelled
```

规则：

- `draft` 只能由数据编辑员配置；
- `queued/running` 受来源权限、预算和并发限制；
- `paused` 可以因为限流、来源条款变化、连续失败或人工操作产生；
- `completed` 只表示批次执行完，不改变候选审核状态；
- `partially_failed` 必须有成功、失败、排除三类清单；
- 同一批次通过 `operation_intent_id` 幂等，重试不能重复创建来源记录或关系。

### 5.2 批次最小信息

每个批次至少记录：

- `batch_id`、城市和采集范围；
- source registry/field dictionary 的 ID 与 SHA-256；
- collector 和 parser 版本；
- 触发人、触发时间和任务参数摘要；
- 请求数量、成功数量、限流数量、失败数量和排除数量；
- 结果资产哈希、失败/排除原因和下一次重试时间；
- 是否生成候选 Revision、关系线索和审核任务。

## 6. 归一化、去重与 Revision 策略

### 6.1 地点归一

先去除空白、全角半角差异和无意义标点，再结合官方名称、别名、地址、行政区域、Provider ID 和几何范围形成合并候选。名称相似只能触发人工关注，不能单独合并地点。

### 6.2 去重结果

去重程序输出三种结果：

| 结果 | 含义 | 后续动作 |
|---|---|---|
| `same_entity` | 多来源确认是同一地点 | 合并到同一 Place，来源分别保留 |
| `possible_duplicate` | 可能重复但证据不足 | 进入 O06/数据编辑待处理清单 |
| `distinct_entity` | 业务上应分别选择 | 各自创建 Place，不生成重复关系 |

### 6.3 Revision 生成

- 新地点生成 `candidate` Revision；
- 已有地点事实发生变化，创建新的 Revision，不原地覆盖已发布 Revision；
- 新采集结果只进入 candidate/staging；
- 旧来源失效时保留历史来源，新增替代来源并重新绑定子证据；
- 采集变化自动清除新 Revision 的审核/求解资格，必须重新送审。

## 7. 关系识别与导入

关系由规则管道生成，不由审核员凭空新增。识别程序必须输出：

```json
{
  "clue_id": "stable-relation-id",
  "left_candidate_id": "candidate-a",
  "right_candidate_id": "candidate-b",
  "relation_candidate": "contains",
  "reason_code": "OFFICIAL_PARENT_CHILD_DESCRIPTION",
  "evidence_source_record_id": "source-a",
  "detector_version": "relation-detector-v1",
  "confidence": 0.94,
  "review_status": "unresolved"
}
```

当前数据库导入规则：

1. 两端 Place 都存在时才创建 `place_relations`；
2. 缺少另一端时延迟到后续批次；
3. `clue_id` 和 `(from_place_id, to_place_id, relation_type)` 保证幂等；
4. 来源记录失效时关系不能进入发布门禁有效集合；
5. 已人工裁决的关系不能被重新采集覆盖；
6. 关系新增、变化和撤回必须创建新 Revision 或待重新审核状态；
7. O07 只展示、裁决和审核，不提供任意手工新增关系入口。

关系语义和误识别/漏识别处理以 [O07 规则文档](../specs/place-relation-detection-rules.md) 为准。

## 8. AI 辅助抽取边界

AI 可以做：

- 从已允许的官方公告中定位年份、日期和事件段落；
- 将公告候选结构化为日期、时间、闭馆/开放类型；
- 从官方页面识别“位于、包含、园内”等层级语义；
- 提供字段候选值、证据片段和置信度；
- 生成供审核员阅读的差异摘要。

AI 不可以做：

- 自行决定来源是否合规；
- 自行把结果写入 `human_verified` 或 `published`；
- 没有证据时猜测开放时间、入口、时长或关系；
- 以置信度替代人工核验；
- 把网络超时、TLS 失败或页面不可达解释为“官方尚未发布”。

AI Tool 必须是只读建议或创建待执行采集任务的入口，实际写入仍由确定性服务完成并接受权限、审计、版本和发布门禁。

## 9. 失败、限流和过期

失败按以下类别处理：

- `source_rejected`：来源或字段不被允许，立即拒绝；
- `rate_limited`：遵守 Retry-After、退避和每日预算；
- `temporary_network_error`：有限次数重试，不能伪装成无数据；
- `parse_failed`：保留非敏感错误摘要，进入人工关注；
- `schema_changed`：暂停该来源，等待解析器升级；
- `evidence_conflict`：生成 O06 待处理项；
- `stale_source`：来源超过有效期或条款变化，暂停新增事实。

采集器必须具备：

- 每来源速率限制和每日预算；
- 指数退避、熔断和手动恢复；
- Provider 响应缓存与 TTL；
- 请求去重和批次幂等；
- 失败/排除清单；
- 不把缺边、空响应或解析失败填成默认值 0、全天开放或无关系。

## 10. 管理端设计

OM1 先提供简化工作台：

1. “新建采集批次”：选择已登记来源、城市/区域和目标字段；
2. “执行状态”：显示运行、限流、失败和待重试；
3. “结果摘要”：显示新增候选、变更候选、关系线索和冲突数量；
4. “差异预览”：展示来源值、候选值、旧 Revision 值和证据链接；
5. “送人工审核”：批量创建 candidate Revision 和 O04/O05/O06/O07 待办；
6. “回放”：按批次、来源版本、解析器版本和输入哈希复现结果。

业务人员不接触：JSON、API Key、Cookie、内部数据库连接串、关系主键或分钟数。高级追溯信息只在需要时展开。

OM2 再增加多城市、任务调度、质量看板、过期提醒、双人复核和来源变更订阅。

## 11. 代码架构与数据边界

建议保持模块化单体，新增端口如下：

```text
application/data_collection/
  create_batch.py
  run_batch.py
  reconcile_candidates.py
  detect_relations.py
  build_revision.py
domain/data_collection/
  CollectionBatch
  CollectionAttempt
  CollectionResult
  RelationClue
infrastructure/collection/
  gaode_collector.py
  official_page_collector.py
  announcement_parser.py
  cache.py
```

依赖方向：

```text
Collector → SourceRegistry / ProviderAdapter
Parser → FieldDictionary
Normalizer → PlaceCatalog
RelationDetector → PlaceCatalog + Evidence
RevisionBuilder → PlaceRevision / SourceRecord
ReviewWorkflow → O04/O05/O06/O07
```

Collector 不得直接依赖发布用例；AI adapter 不得直接依赖 ORM；所有外部请求通过 Provider 端口，便于限流、缓存、替换和测试。

## 12. API 与权限草案

| API | 权限 | 作用 |
|---|---|---|
| `POST /api/v1/admin/collection-batches` | `data_editor` | 创建待执行批次 |
| `POST /api/v1/admin/collection-batches/{id}/run` | `data_editor` | 启动受控批次 |
| `POST /api/v1/admin/collection-batches/{id}/pause` | `data_editor` | 暂停批次 |
| `GET /api/v1/admin/collection-batches/{id}` | `research_viewer` | 查看状态、结果和失败清单 |
| `GET /api/v1/admin/collection-batches/{id}/diff` | `data_editor` | 查看候选/Revision 差异 |
| `POST /api/v1/admin/collection-batches/{id}/materialize` | `data_editor` | 将合规结果生成 candidate Revision |
| `POST /api/v1/admin/collection-batches/{id}/submit-review` | `data_editor` | 创建 O04–O07 审核待办 |

任何 API 都必须校验来源 registry、字段字典、目标阶段、批次版本、权限、幂等键和审计原因。没有“直接发布采集批次”的 API。

## 13. 测试与退出条件

### M1/OM1 最小闭环

- 高德候选采集可生成版本化候选目录；
- 来源不合规、字段越权、凭证泄露和 conditional 越级均被拒绝；
- 归一、去重、关系线索和批量导入可重复；
- 部分批次失败不污染成功数据；
- 关系两端缺失时延迟，不创建孤立关系；
- 新 Revision 不覆盖旧审核/发布结果；
- O04/O05/O06/O07 可以接收采集结果并完成人工闭环；
- 审计可以回答“谁、何时、用哪个来源和规则版本生成了什么结果”；
- 失败、重试、暂停、恢复和 dry-run 均有自动化测试。

### M2/OM2 扩展退出条件

- 至少两个来源适配器和两个城市的受控批次；
- AI 抽取结果有证据定位、置信度和人工采纳率指标；
- 字段级跨来源冲突能展示来源值并可逐项裁决；
- 过期来源、条款变化和解析器变更可自动暂停；
- 批次差异、回放、失败重试和质量看板通过 Chrome 验收；
- 无凭证、无未授权内容、无越级 published 写入。
