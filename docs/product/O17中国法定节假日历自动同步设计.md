# O17 中国法定节假日历自动同步设计

- 文档版本：V1.0
- 决策状态：已接受，实现中（确定性同步内核第一切片已完成）
- 管理侧里程碑：OM1
- 支撑用户里程碑：M1
- Gate 7 工作包：G7-R0.2-09
- 当前范围：中国大陆
- 关联决策：ADR-0021

## 1. 产品目标

系统无需业务人员逐年手工录入法定节假日。管理员可以点击“同步节假日历”，后台也可以周期性自动检查；系统从中国政府官方公告获取年度安排，使用 AI 转为结构化数据，经确定性规则校验后发布年度日历，供 O05 批量生成地点日期例外。

正常年份实现零人工录入、零人工审批；只有官方来源不可访问、公告结构异常、AI 抽取失败、日期冲突或官方内容变化无法自动判定时，才进入异常处理。

## 2. 非目标

OM1/M1 本节点不做：

- 港澳台及外国节假日；
- 省市级地方性假期；
- 使用新闻、百科、攻略或搜索摘要作为最终来源；
- 让通用大模型直接操作数据库或直接设置 published；
- 用上一年度日期平移、模型记忆或算法猜测未发布年度；
- 因调休工作日自动改变地点开放规则；
- 静默覆盖已发布年度版本和已生成的地点日期例外。

## 3. 页面与入口

管理端新增一级入口：

```text
基础数据
└── O17 中国法定节假日历
```

页面主要区域：

1. 年度覆盖摘要；
2. 日历版本列表；
3. 最近同步任务；
4. 异常与待处理项；
5. “同步节假日历”按钮。

### 3.1 年度覆盖摘要

展示：

- 当前年份是否已发布；
- 下一年份是否已发布；
- 最远可规划日期对应年份是否有日历；
- 下一次自动检查时间；
- 最近一次官方来源检查结果。

当允许规划的日期跨入无日历年份时显示高优先级告警：

```text
2027 年中国法定节假日历尚未发布，涉及 2027 年的“节假日开放/顺延闭馆”规则暂不能自动生成。
```

### 3.2 同步操作

点击“同步节假日历”后只选择年份：

```text
同步年份：2027
[开始同步]
```

不要求管理员填写 URL、节日名称、日期、JSON、内容哈希或版本号。

### 3.3 列表字段

| 字段 | 中文展示 |
|---|---|
| 年份 | 2027 |
| 版本 | 第 1 版 |
| 状态 | 尚未发布 / 同步中 / 已发布 / 需要处理 / 已被替代 |
| 公告来源 | 国务院办公厅 |
| 公告发布日期 | 官方发布日期 |
| 节假日范围 | 7 段或合并后的实际数量 |
| 放假日期总数 | 结构化日期去重后的数量 |
| 调休工作日 | 已记录数量 |
| 最近检查 | 时间和结果 |
| 使用情况 | 被多少个地点/Revision 使用 |

内部 calendar ID、内容哈希和同步任务 ID 只放在折叠追溯区。

## 4. 统一同步架构

```text
O17 同步按钮 ─────────┐
                       │
后台周期任务 ──────────┼→ ChinaHolidayCalendarSyncService
                       │
AI Tool ───────────────┘
                            │
                            ├─ 官方公告发现器
                            ├─ HTML/PDF/附件获取器
                            ├─ AI 结构化抽取器
                            ├─ 确定性校验器
                            ├─ 版本与差异服务
                            └─ 审计与发布门禁
```

前端、定时任务和 AI Tool 不得各自维护抓取逻辑。

## 5. 官方来源发现

### 5.1 允许来源

首版只接受 Source Registry 中已批准的中国政府官方来源，至少覆盖：

- 中国政府网 `gov.cn`；
- 国务院办公厅正式通知；
- 正式通知页面绑定的官方附件。

搜索服务只用于发现可能的官方 URL。最终事实必须重新打开并验证官方 URL，不能使用搜索结果摘要。

### 5.2 公告识别

候选公告至少校验：

- 标题包含目标年份和节假日安排语义；
- 发布主体为国务院办公厅或审核通过的等价官方主体；
- 页面/附件来源仍位于允许域名；
- 正文年份与请求年份一致；
- 页面不是转载、解读或历史归档误匹配。

## 6. AI 抽取契约

AI 只输出受限 Schema：

```json
{
  "region": "CN",
  "year": 2027,
  "source_title": "国务院办公厅关于2027年部分节假日安排的通知",
  "periods": [
    {
      "name": "春节",
      "start": "2027-02-05",
      "end": "2027-02-11",
      "evidence_quote": "春节：2月5日至11日放假调休……"
    }
  ],
  "adjusted_workdays": [
    {
      "date": "2027-01-31",
      "holiday_name": "春节",
      "evidence_quote": "1月31日、2月20日上班"
    }
  ]
}
```

AI 不输出生命周期状态、版本号、审核结果或 published 决定。

## 7. 确定性校验

自动发布前必须全部通过：

1. 官方来源渠道与域名白名单；
2. 请求年份、标题年份、正文年份一致；
3. `start <= end`；
4. 不同节假日日期无无法解释的重叠；
5. 放假日期与调休工作日不冲突；
6. 节日概念覆盖元旦、春节、清明、劳动节、端午、中秋、国庆，允许官方合并中秋/国庆；
7. 每条记录有原文证据片段；
8. 原始内容有 `source_url/observed_at/content_sha256`；
9. 规范化载荷可以生成稳定 digest；
10. 同内容重复同步幂等；
11. 内容变化创建新版本；
12. 审计事件写入成功。

任何一项失败都不得发布。

## 8. 同步状态与用户提示

| 状态 | 触发条件 | 页面提示 |
|---|---|---|
| `not_announced` | 官方发现过程成功，但没有目标年份正式公告 | “2027 年法定节假日安排尚未发布” |
| `temporarily_unavailable` | 网络、TLS、超时、官方站点故障 | “暂时无法确认公告状态，请稍后重试” |
| `needs_attention` | 找到公告但来源/解析/校验失败 | “发现官方公告，但结构化校验未通过” |
| `validated_preview` | preview 模式已通过校验，但未写入发布版本 | “预览校验通过，尚未发布” |
| `published` | 新版本全部门禁通过并发布 | “2027 年日历已同步并发布” |
| `up_to_date` | 当前官方内容与已发布版本一致 | “当前已是最新版本” |
| `superseded` | 同年度新版本替代旧版本 | “已被第 N 版替代” |

`not_announced` 是正常业务结果，不使用红色错误样式；网络失败绝不能伪装为 `not_announced`。
`validated_preview` 只用于预览任务，不等同于 `published` 或 `up_to_date`，O05 不得读取。

## 9. AI Tool 设计

Tool 名称：

```text
sync_china_holiday_calendar
```

输入：

```json
{
  "year": 2027,
  "mode": "preview"
}
```

`preview` 只发现、抽取和校验；`sync` 允许应用服务在门禁通过时发布。

返回：

```json
{
  "year": 2027,
  "status": "not_announced",
  "message": "2027 年法定节假日安排尚未发布",
  "checked_at": "2026-09-02T17:30:00+08:00",
  "next_check_at": "2026-09-03T09:00:00+08:00"
}
```

Tool 不接受任意来源 URL，不接受模型直接提供的日期事实，不返回或接收数据库凭证。

## 10. 计划管理 API

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `GET /api/v1/admin/holiday-calendars` | 管理只读角色 | 查询年度版本和状态；O05 默认只取 published |
| `POST /api/v1/admin/holiday-calendar-sync-jobs` | data_editor/admin_security | 创建同步任务，参数只含地区、年份、模式和 operation intent |
| `GET /api/v1/admin/holiday-calendar-sync-jobs` | 管理只读角色 | 查询最近任务、状态和失败原因 |
| `GET /api/v1/admin/holiday-calendar-sync-jobs/{job_id}` | 管理只读角色 | 查询来源、抽取、校验和发布结果 |
| `POST /api/v1/admin/holiday-calendar-sync-jobs/{job_id}/cancel` | data_editor/admin_security | 取消尚未领取或等待重试的任务；运行中的任务不强制终止 |
| `POST /api/v1/admin/holiday-calendar-sync-jobs/{job_id}/confirm` | data_editor/admin_security | 提交业务人员核对或调整后的预览数据；服务端重新执行确定性校验，通过后原子发布新版本 |
| `GET /api/v1/admin/holiday-calendars/{calendar_id}` | 管理只读角色 | 查询结构化节假日、调休、来源和版本历史 |
| `GET /api/v1/admin/holiday-calendars/{calendar_id}/impact` | 管理只读角色 | 查询新版本对已物化地点日期例外的影响；仅统计具备日历来源追溯的记录 |

同步采用异步 Job；HTTP 请求不等待外部抓取和 AI 推理全部结束。

预览确认不再创建第二个 AI 抓取任务。业务人员可在确认弹窗中修改节假日名称、起止日期、调休日期及官方原文依据，也可增删记录。确认接口只接受原 `validated_preview` 任务，沿用其官方公告 URL、标题和正文指纹，并重新校验年度、日期范围、区间重叠、节假日与调休冲突、七类法定节日完整性和原文依据；任一条件不满足时不写入。通过后在同一事务中生成不可变 Calendar Version、替代旧版本并写管理审计。相同确认意图的网络重试返回原结果，不重复创建版本。

## 12. 周期同步

首版策略：

```text
每年 9 月 1 日至 12 月 31 日：每天检查下一年度一次
下一年度发布成功后：改为每周检查官方内容哈希
当前或下一年度缺失且已进入规划窗口：立即告警并允许手工触发同步
```

连续失败采用指数退避；不得高频请求政府网站。相同年度同一时刻只允许一个运行中的同步任务。

## 13. 官方变更和地点影响

官方内容变化时：

```text
v1 内容哈希变化
→ 抽取并校验 v2
→ 发布 v2
→ v1 标记 superseded
→ 计算受影响日期和地点
→ 不修改历史 PlaceDateException
```

已使用旧日历生成、审核或发布的地点记录保持不变。后续可在 OM2 增加批量创建受影响地点候选 Revision；OM1 先提供影响查询和明确待办。

## 14. 权限与审计

AI/定时任务使用受限系统主体，不能冒充人工管理员。至少记录：

- `HOLIDAY_CALENDAR_SYNC_STARTED`
- `HOLIDAY_CALENDAR_NOT_ANNOUNCED`
- `HOLIDAY_CALENDAR_SOURCE_FETCHED`
- `HOLIDAY_CALENDAR_PARSED`
- `HOLIDAY_CALENDAR_VALIDATION_FAILED`
- `HOLIDAY_CALENDAR_PUBLISHED`
- `HOLIDAY_CALENDAR_UP_TO_DATE`
- `HOLIDAY_CALENDAR_VERSION_SUPERSEDED`

审计保存来源 URL、内容摘要、结果码和任务关联，不保存网页凭证、模型密钥或无必要的完整网页正文。

## 15. 验收矩阵

1. 已发布年度重复同步返回“已是最新版本”，无重复行；
2. 未发布年度返回 `not_announced`，数据库无伪日历；
3. 网络超时返回 `temporarily_unavailable`；
4. 非官方转载被拒绝；
5. AI 日期重叠或缺失节日时进入 `needs_attention`；
6. 正常公告自动发布，O05 下拉可见；
7. 同步按钮、定时任务、AI Tool 使用同一结果；
8. 官方内容变化创建 v2，v1 和历史地点例外不变；
9. O05 仍只生成 candidate 日期例外，并继续逐项核验；
10. 全流程有可查询审计，日志与业务审计分离。
