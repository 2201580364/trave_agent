# AI 协作开发 Gate 与权威来源

> 本文件定义阶段退出准则、资料冲突处理和决策变更传播要求。Gate 结论必须基于仓库证据，不以对话中的口头总结代替。

## 权威来源优先级

发生冲突时按以下顺序处理：

1. 最新且状态为「已接受」的 ADR；
2. 当前状态为 Accepted 的需求规格；
3. `docs/domain/` 领域规范与 `docs/specs/data-model.md`；
4. `docs/assumptions.md` 假设登记册；
5. `.claude/rules/`、`.claude/skills/`、`.claude/agents/`；
6. 产品/技术选型历史文档；
7. Spike README、Spike 代码与示例数据。

若同级权威来源互相冲突，停止实现，列出冲突、影响范围和建议决策；不得静默选择其中一版。Spike 只提供证据，不定义生产语义。

## G0–G7 Gate

### Gate 0：假设可验证

- 假设有 `H-x` 编号、验证方式和失效判据；
- 陈述可被证伪，不是愿望或功能描述；
- 标明验证阶段与所需证据。

### Gate 1：用户问题有真实证据

- 研究记录来自真实访谈/行为，不得由 AI 虚构；
- 结论能回溯原始记录；
- 明确样本、局限与对 H-x 的影响。

### Gate 2：需求可验收

- Given/When/Then 可执行；
- 正常、边界、异常与降级路径明确；
- 每条验收标准关联 H-x、约束编号和指标；
- 主观词已拆成客观指标与用户指标。

### Gate 3：高风险技术已有证据

- Spike 有预先定义的成功/失败判据和时间盒；
- 保存原始结果、环境、局限；
- 结论明确是继续、调整还是放弃；
- 形成长期决策时写 ADR。

### Gate 4：设计冻结且 AI 控制面同步

- 目标函数、硬/软约束、降级策略和数据模型明确；
- ADR 包含备选方案、后果和重议触发条件；
- solver-review、test-review 无开放 P0；
- `CLAUDE.md`、rules、skills、agents、specs、domain、tests 与 Accepted ADR 一致；
- 仍未实现的降级项被明确标注，不伪装为已完成能力。

### Gate 5：约束切片实现完成

- 任务开始前声明 H-x、规格、C-x/S-x、ADR、范围与验证方式；
- 先有失败测试，再有最小实现；
- 对应单测、全量测试和静态检查通过；
- 不把 Spike 代码直接视为生产实现。

### Gate 6：分层验证通过

- C1/C2/C4/C5/C6 违反数为 0；
- Golden Case 可执行并保存报告；
- 数据门禁、性能、降级和可复现性测试通过；
- 测试可追溯到 H-x 与约束编号。
- M1 求解器公开契约、参数版本、拒绝码和搜索状态已生成机器快照并通过漂移测试；契约冻结后转入应用功能模块与页面设计。

### Gate 7：假设结论有足够证据

- 区分 Spike、自动化测试、专家评审、用户测试和线上数据；
- 记录样本量、数据区间、原始证据、限制和反例；
- 技术证据不得替代用户认可证据；
- 结论回写 `docs/assumptions.md`，并做数据/算法/交互归因。

## 决策变更传播检查

新增或修订 ADR 后，逐项检查：

- [ ] `docs/assumptions.md`
- [ ] `docs/specs/`
- [ ] `docs/domain/`
- [ ] 数据模型与 API 契约
- [ ] 测试与 Golden Cases
- [ ] `CLAUDE.md`
- [ ] `.claude/rules/`
- [ ] `.claude/skills/`
- [ ] `.claude/agents/`
- [ ] Spike 文档是否需要标注「历史/已废弃」

## G5 任务开始协议

每个实现切片开始前记录：

```text
任务：<名称>
关联假设：H-x
规格：<文件/验收标准>
约束：C-x / S-x
依据 ADR：ADR-xxxx
包含：<本次实现范围>
不包含：<明确排除>
验证：<单测 / Golden Case / 性能 / 静态检查>
```
