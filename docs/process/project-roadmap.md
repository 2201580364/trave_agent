## 1. 路线图回答什么

本项目同时使用五套坐标，必须分开理解：

| 坐标 | 用途 | 当前值 |
|---|---|---|
| `M1–M4` | 产品能力里程碑 | M1 后段，尚未通过用户验证 |
| `OM1–OM4` | 管理侧能力里程碑 | OM1 产品设计、身份/API/审计后端底座和 admin-web 安全操作面已完成；地点审核、OD 和发布待实现 |
| `G0–G7` | 假设与证据 Gate | Gate 7 进行中；Gate 1 存在真实用户研究补证债务 |
| `A1–A6` | M1 产品工程设计与纵向切片 | A1–A6 已完成首轮，后续按 Gate 7 发现补修 |
| `R0–R3` | Gate 7 准备、形成性、确认性和真实行为验证轮次 | R0.2-05-02 当前节点 |

`P0/P1/P2` 只表示当前 M/OM 里程碑的实现优先级，不表示产品阶段；历史机器 ID 中的 `p1` 也不表示产品路线。管理侧原子功能使用 `ADM-*`，页面使用 `O00–O16`。

## 4. 总体产品路线

```text
M1 行程骨架验证
→ M1 Gate 7 价值结论与受控发布
→ M2 信息增强、决策辅助、行程执行与旅行小记
→ M3 行前/行中动态服务、预订、评分讨论与治理
→ M4 跨行程记忆、自动游记、多人协同与用户生态
```

管理侧按对应用户能力前置演进：

```text
OM1 研究数据治理与受控发布 ───────→ 支撑 M1 / Gate 7
OM2 多目录、媒体与授权治理 ───────→ 支撑 M2
OM3 社区与实时服务治理 ───────────→ 支撑 M3
OM4 共创、AI 内容与生态治理 ──────→ 支撑 M4
```

OM 不是第五条用户功能路线。管理侧 P0 门禁未就绪时，对应用户能力不得对外开放；管理端设计完成也不等于对应 OM 里程碑实现完成。

进入后续里程碑不是按日期自动发生，而是由上一里程碑证据决定：

- M1 未证明 H3，不直接扩大城市和功能；
- M2 未证明 H8/H9/H10，不直接建设重型内容与推荐网络；
- M3 社区治理未就绪，不开放评分讨论区；
- M4 没有足够跨行程行为和授权素材，不提前训练或推断长期人格。

原产品文档中的“4 个月 / 5 个月 / 5 个月”只作为完整团队投入下的早期工作量参考，不是当前承诺日期。实际排期必须在每个里程碑启动时根据人员、外部 API、审核和用户研究资源重估。

### 5.4 G1 真实发现研究补证

该研究不依赖 H5 或杭州 published snapshot，可与 R0.2–R0.4 并行准备和执行；为避免用未经校准的画像招募 Gate 7 参与者，应在 R1 外部招募锁定前关闭，而不是拖到 M1 最终复盘。推荐 8–10 名符合目标画像的自助旅行用户：

- 记录最近一次攻略行为、耗时、工具、痛点和放弃点；
- 验证 H4：信息过多难取舍是否优先于信息不足；
- 校准目标画像、旅行频次、AI 信任门槛和大交通决策顺序；
- 保存去标识研究结论和对 assumptions 的回写；
- 不把该研究样本自动并入 H3 `n>=21` 的确认性分母；如复用参与者，必须在 protocol 中预先说明并避免诱导。

### 5.6 M1 里程碑决策

Gate 7 复盘后只有三种结论：

1. **进入受控发布**：H3 得到支持，核心 blocker/major 为 0，数据和环境门禁通过；
2. **M1 补修后重测**：证据为需调整，明确归因和版本，不扩大到 M2 掩盖问题；
3. **停止或重构定位**：H3 被推翻，或 G1 发现用户核心问题与当前产品不一致。

进入受控发布也不等于稳定生产。后续顺序为：

```text
受控 H5 小流量试运行
→ 微信小程序体验版渠道差异验证
→ 分享/登录/隐私/内容审核等发布前补齐
→ 微信小程序备案、审核和正式发布
→ M1 受控上线目录逐步扩至 80–120 个 Place
```

## 10. 里程碑完成定义

一个里程碑只有同时满足以下条件才可标记完成：

1. **产品**：范围内用户侧 P0 已形成用户可完成的闭环，所需管理侧 P0 已形成运营可完成的治理闭环；
2. **数据**：所需城市、地点、内容和 Provider 达到发布门禁；
3. **工程**：代码、迁移、部署、备份、恢复和可观测性通过；
4. **质量**：自动化、Golden、降级、性能、安全和真实浏览器通过；
5. **证据**：相关 H-x 达到预注册阈值或明确被推翻/调整；
6. **文档**：ADR、规格、领域、API、数据、UI、交互、测试、运维和状态同步；
7. **边界**：未实现能力、已知风险和下一里程碑依赖被诚实登记。

工程切片完成、服务器启动、自动化测试通过或文档完成，任何一个单独条件都不能替代里程碑完成。

## 11. 每轮推进规则

每完成一个工作包：

1. 更新 `project-status.md` 的当前节点、证据、遗留和下一步；
2. 只在路线结构或里程碑顺序变化时更新本文件；
3. 行为决策写 ADR，验收行为写 specs/domain，不把所有细节堆入路线图；
4. 修改已锁 protocol 必须创建新版本，不能静默覆盖；
5. 不以百分比掩盖门禁，优先报告“已通过/未通过/不可评价”；
6. 下一任务始终从当前节点的退出条件反推，不因新想法跳过数据、部署或验证依赖。
7. 管理端状态单独报告“已设计/已实现/已部署/已验收”，不得用用户端完成度或数据库表存在替代。
